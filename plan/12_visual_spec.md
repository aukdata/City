# ビジュアル仕様書

Siv3D v0.6.16 を前提とした描画設計。
平成〜令和の日本の景観を3D見下ろし視点で表現する。

---

## 1. 全体方針

- **スタイル**: 日本の地方都市を実寸と素材感に基づくリアル寄りの3Dで表現する（2026-09-11 ユーザー指定）
  - 建物は実写素材、立体的な窓枠・バルコニー・屋根材・設備、局所AOの焼き込みを使用する
  - 車両は簡略化したローポリ
  - 木・電柱・信号機など街路要素はシルエット重視
- **時代感**: ゲーム内年代（初期: 昭和末〜平成初期）に応じてアセットを切り替え
- **カラーパレット**: 日本の地方都市らしい落ち着いた色調。青空・田園の緑・アスファルトグレー

## 2.5. 実レンダ検証用カメラ

```text
--capture-city --seed <seed> でゲーム本体を起動すると、UIを非表示にした Capture カメラで
全景、市街地、中景、農地縁辺、交差点俯瞰、複数交差点の斜めズーム、道路標示確認用の低角ズーム、交差点真上、街角、海岸バッファ、農地利用の22視点を App/Screenshot/city_generation/ に保存する。
Test専用描画は使わず、通常の WorldRenderer / RoadRenderer / GameScene 経由の実レンダのみを対象にする。
レビュアーへは contact_sheet.png だけでなく、交差点ズーム/真上/低角の個別画像も渡し、道路標示のはみ出し、横断歩道の向き、生活道路外側の不要な緑帯を判定させる。
```

| 農地（畑） | 畝模様 | 茶〜黄 |

### 季節変化

```
春（3〜5月）: 桜（薄ピンク）・新緑
```

## 6. 地形の凹（掘割・トンネル）

道路・線路の標高と地形標高を比較して掘割・トンネルを自動判定する。
プレイヤーは種別を明示的に選ばない。

```
道路/線路の標高 < 地形標高 のとき:

  上部に地形（土被り）あり？
    YES → トンネル
    NO  → 掘割

  判定閾値: 土被り < 3m は掘割として扱う（薄すぎるトンネルを防ぐ）
```

### 掘割（切土）

ハイトマップ自体を変形させて表現する。

```
道路/線路敷設時（1回だけ実行）:

① ベジェ曲線に沿って道路標高でハイトマップを上書き
   （道路幅 + 法面幅の範囲を掘り下げる）

② 掘削境界から左右に法面メッシュを自動生成
   勾配: 1:1.5（高さ1に対して水平1.5）

③ 法面テクスチャ: 砂利・岩肌（地質タイプ依存）
   吹付けコンクリート or 緑化（成長段階に応じて変化）

④ チャンク境界で分割して各チャンクのハイトマップを更新
   → 隣接チャンクのメッシュ再生成をトリガー
```

### トンネル

レンダリングメッシュにブーリアン穴あけを行う。ハイトマップは変更しない。

```
トンネル区間確定時（1回だけ実行）:

① ベジェ曲線に沿ったトンネル断面をXZ平面に投影し
   フットプリント（細長い多角形）を取得

② 対象チャンクのレンダリングメッシュを走査
   フットプリントと重なる三角形を検出

③ 重なる三角形を削除し、境界をリトライアングル
   （Sutherland-Hodgman クリッピング）
   → 地形メッシュにトンネル形状の穴が開く

④ トンネル内壁メッシュを生成
   天井: アーチ形 or 矩形（道路: コンクリート、鉄道: レンガ or コンクリート）
   側壁: コンクリート打ち放し
   路面: 通常の道路路面テクスチャ
   → 描画レイヤー 3（道路下地）に配置

⑤ 坑口（ポータル）メッシュを入口・出口に配置
   コンクリート枠 + 扁額（銘板）

注意:
  ・ハイトマップデータは変更しない（経路探索・地形判定は従来通り）
  ・変更するのは描画用レンダリングメッシュのみ
  ・チャンクをまたぐトンネルはチャンク境界でメッシュを分割して処理
```

### 一人称視点でのトンネル内部

```
カメラがトンネル内に入ったとき:
  → 穴あけ済みのため地形メッシュは存在しない
  → 内壁・天井メッシュが自然に見える
  → 出口に向かって外光（白い環境光）が差し込む表現
```

### 視覚比較

| | 掘割 | トンネル |
|--|------|---------|
| ハイトマップ | 変更する | 変更しない |
| レンダリングメッシュ | ハイトマップから再生成 | ブーリアン穴あけ |
| 法面メッシュ | 自動生成 | なし（坑口のみ） |
| 内壁メッシュ | なし | 自動生成 |
| 俯瞰での見え方 | 地形が凹む | 穴から内部が見える |

## 7. 道路

### スタイル外部定義システム

道路の外観（色・テクスチャ・車線区画線）は `App/assets/styles/road.toml` で定義する。
実際の車線数は `RoadEdge.lanes` が保持し、スタイルファイルには含めない。

```
主要パラメータ（道路種別ごとに設定）:

  [路面]
  surface_texture    テクスチャ画像パス（空文字 = 単色フォールバック）
  surface_color      路面色 [R, G, B]
  surface_tile_v     走行方向 UV タイリング [1/m]（大きいほど細かい）

  [断面寸法]
  default_lane_width 標準車線幅 [m]（新規道路追加時のデフォルト）
  shoulder_width     路肩幅 [m]（片側）
  median_width       中央分離帯幅 [m]（0 = なし）

  [車線区画線] （lane_marking サブテーブル）
  color              線色 [R, G, B]
  line_width         線幅 [m]
  dash_length        破線の実部長 [m]（0 以下 = 実線）
  gap_length         破線の間隔長 [m]

  [センターライン] （center_line サブテーブル）
  ※ 対向車線境界に適用。一般道: 黄実線、高速: 白実線
```

#### C++ スタイル型階層

```
RoadPartDef         部品アセット定義（OBJ + TOML、16_road_cross_section_spec.md 参照）
RoadPart            道路上の部品インスタンス（defId + width + offset + BuildState）
Lane                車線（位置・方向・供用状態・区画線、07_road_lane_spec.md 参照）
LineType            区画線種別（SolidWhite / DashedWhite / SolidYellow / DoubleYellow）
```

部品アセット: `App/assets/road_parts/` に TOML + OBJ のペアで配置。
旧 RoadStyle / RoadStyleRegistry は RoadPartDef + プリセット構成に移行予定。

### 路面描画

```
RoadEdge の各 RoadPart ごとに独立した帯メッシュを生成。

各部品の OBJ モデルから断面形状を取得:
  inner + center × N + outer で目標幅の断面を構成
  ベジェ曲線に沿ってサンプリングし帯メッシュ化

UV:
  u: 0 = 左端、1 = 右端（部品ごと）
  v: arc_length × surface_tile_v（走行方向にタイリング）

区画線は Lane の lineLeft / lineRight に基づいて車線ごとに個別生成。
```

### 車線区画線

```
RoadEdge.lanes の車線配列から境界位置を計算してポリゴン帯を生成。
地形ハイトマップに追従（路面より 2.05m 浮かせて Z-fighting 回避）。

境界の種別判定:
  方向が変わる境界（Forward↔Backward）→ center_line スタイル
  同方向車線間の境界               → lane_marking スタイル

実線: dash_length ≤ 0 のとき連続帯
破線: bezier を 2m 刻みで分割し、中点の位相でオン/オフ判定
```

### 道路種別ごとのデフォルト外観（road.toml）

| 種別 | 路面色 | 路肩 [m] | 中央分離帯 [m] | センターライン |
|-----|--------|---------|--------------|--------------|
| LocalRoad | グレー (0.36) | 0.5 | なし | 黄実線 |
| Arterial | 濃グレー (0.30) | 0.75 | なし | 黄実線 |
| Expressway | 暗グレー (0.25) | 1.5 | 3.0 | 白実線 |
| Highway | 最暗グレー (0.23) | 1.5 | 5.0 | 白実線 |

### 建設中の見た目

```
BuildState:
  UnderConstruction: 土色の路盤・工事フェンス・クレーン（大型工事）
  NotBuilt（計画線）: 半透明の点線プレビュー（道路計画モード時のみ表示）
  StubEnd（イカの耳）: 橋台・法面・バリケード
```

### オーバーレイ（Hキー: 渋滞ヒートマップ）

```
道路 congestion 値を色で表示（路面の上に半透明レイヤー）:
  0〜40%: 緑
  40〜70%: 黄
  70〜90%: オレンジ
  90〜100%: 赤
```

## 8. 建物

### 基本形状

建物はゾーン・種別・成長段階に応じた箱型メッシュ＋屋根で表現。

### 現行実装（2026-04）

現行の描画は「全建物を箱型」ではなく、**OBJ モデル建物** と **色付き Box 建物** の併用になっている。

```text
OBJ で描画:
  Detached / LowApartment / MidApartment / HighApartment
  Shop / Office

Box で描画:
  Factory / ParkBuilding / PublicFacility / Parking

低層ディテールメッシュで描画:
  Farmland / 舗装ロット / 公園面 / 駐車場面 / 敷地境界
```

- 住宅系 OBJ は `assets/buildings/residential/residential_001..010`
  - グローバルゾーンセル座標ハッシュからバリアントを選ぶ
- 商業 OBJ は現状 `shop_001`〜`shop_003`, `office_001`〜`office_002`
- OBJ は対応する `.toml` の `scale` / `render_scale` を読み、遅延ロードして共有キャッシュする
- OBJ は種別ごとの目標フットプリントに収まるよう、モデル外接サイズからスケールを正規化する
- Box 建物は `buildingHeight(type)` をメートル基準の高さとして使う簡易メッシュ
- 初期生成の建物占有幅は種別ごとに9〜14mとし、配置判定と描画で共通化し、敷地の余白へ庭・駐車場・塀を置く
- 建物はセル中心に固定せず、接道方向や用途に応じたセル内オフセットを持つ
- 接道角 `angle` を持ち、OBJ / Box とも道路方向へ Y 軸回転して描画する
- チャンク単位で建物描画バッチを再構築する
- 市街地セルには舗装面、駐車場、公園面、低い塀などのロット詳細を追加する
- 農地セルは地表付近の細長い区画面と畝で描画する

### 現行 LOD の扱い

- 地形や道路と異なり、**建物専用の距離別 LOD 切替は未実装**
- Box 建物はチャンクごとにマージメッシュ化
- OBJ 建物はインスタンス配列を走査して個別描画
- 選択アウトラインや当たり判定は
  - OBJ 建物: モデル外接ボックス
  - Box 建物: 回転済み `OrientedBox`

| 建物種別 | 形状 | 高さ | 屋根 |
|---------|-----|------|------|
| 戸建て住宅 | 小さい箱 | 1〜2階 | 切妻・寄棟 |
| 低層マンション | 細長い箱 | 3〜4階 | 陸屋根 |
| 中層マンション | 箱 | 5〜8階 | 陸屋根 |
| 高層マンション | 細い高い箱 | 9〜20階 | 陸屋根 |
| 店舗 | 低い横長の箱 | 1〜2階 | 陸屋根・看板 |
| オフィスビル | 箱 | 4〜12階 | 陸屋根・ガラス窓 |
| 工場 | 大きい低い箱 | 1〜2階 | 鋸歯屋根・煙突 |
| 農地 | 低い板状メッシュ | — | 水田・畑の面として地表付近に描画 |
| 公園 | 植栽・ベンチ | — | — |
| 公共施設 | 箱＋エントランス | 2〜4階 | 陸屋根 |
| 駐車場 | 低い格子状 | 1〜3階（立体） | 開放型 |

### 時代感による外観変化

ゲーム内年代に応じてテクスチャを切り替える。

```
1980年代以前（ゲーム開始期）:
  戸建て: 木造和風・瓦屋根・土壁
  店舗: ひさし・手書き看板・昭和フォント
  マンション: 公団スタイル（窓が小さく規則的）

1990年代:
  戸建て: 洋風ハウス・スレート屋根
  店舗: ロードサイド型店舗・蛍光カラー看板
  マンション: バルコニー付き・外断熱

2000年代以降:
  戸建て: ミサワ・積水ハウス風（シンプルモダン）
  店舗: チェーン店ロゴ風看板・大型SCスタイル
  マンション: タワーマンション（高層）
```

### LOD

```
近接（100m以内）: テクスチャ・窓・看板・エアコン室外機
中距離（100〜400m）: テクスチャのみ（ディテールなし）
広域（400m以上）: 単色シルエット（高さのみ）
```

## 9. 車両

### 自動車

VehicleType ごとに形状を変える。すべてローポリ。

| 種別 | 形状の特徴 | 色 |
|-----|----------|---|
| 普通乗用車 | セダン・ハッチバック形 | ランダム（白・シルバー・黒多め） |
| 軽自動車 | 背が高い・短い | ランダム（白・軽トラ含む） |
| 原付 | 細い・2輪 | ランダム |
| 軽車両 | さらに細い・ペダル型 | — |
| バス | 長い直方体・側面に路線色帯 | 白＋路線カラー |
| 小型トラック | キャブオーバー形 | 白・グレー |
| 大型トラック | 長い・箱型荷台 | 白・グレー |
| 緊急車両 | 形状は乗用車 or バン | 白（警察: 白黒、消防: 赤、救急: 白） |

```
サイレン中の緊急車両:
  ルーフ上に点滅するライト（赤 or 青）
  光の円が地面に投影（半径 5m 程度）
```

### 鉄道車両

```
形状: 編成の両数分の車両を連結した直方体列
側面: 路線カラー帯

走行中: 車輪回転・架線スパーク（電化・夜間のみ）
```

### LOD

```
近接（150m以内）: テクスチャ・ホイール・ライト点灯
中距離（150〜600m）: 単色ボディのみ
広域（600m以上）: 非表示（渋滞ヒートマップで代替）
```

```
  遮断機: 赤白縞の棒（アニメーション: 上下回転）

架線柱（電化路線・近接時のみ）:
  H鋼の柱＋横梁＋ビームワイヤー（簡略表現）
```

## 11. 街路要素

```
信号機:
  交差点ノードに自動配置
  赤・黄・青のランプを TrafficLight の状態に連動
  歩行者信号は主要交差点のみ

電柱:
  生活道路・県道沿いに一定間隔で自動配置（15m間隔）
  電線: 電柱間を結ぶ細いライン（近接時のみ）

街路樹:
  バイパス・国道: 中央分離帯に並木（ケヤキ・イチョウ）
  生活道路: まばらに配置（あってもなくても）

バス停:
  ポール＋時刻表プレート（近接時）
  近接時に路線名・時刻が読めるレベルのテクスチャ

標識:
  速度制限標識・一方通行標識・踏切予告標識
  交差点手前・生活道路入口などに自動配置

青看板（案内標識）:
  国道・バイパス・高速道路の交差点・分岐点に自動生成する。
  国土交通省 道路標識設置基準に準拠した2種を実装。
```

### 青看板の種別

| 種別 | 番号 | 用途 | 設置場所 |

### 自動生成ロジック

```
交差点ノード（RoadNode）が国道以上のエッジを持つとき、
接続するエッジの方向ごとに「方面名」と「距離」を決定する。

方面名の決定:
  そのエッジの先にある最も近い「集落名 or 駅名 or IC名」を参照
  PlaceNameDB から取得（最大3方面まで表示）

距離の決定:
  現ノードからその方面の代表ノードまでのグラフ距離 [km]（小数点1桁）

矢印方向の決定:
  各接続エッジの RoadNode からの相対角度をもとに
  「直進」「右折」「左折」「右斜め」「左斜め」の5種から選択

看板の配置:
  「方面及び方向（案内114）」: 交差点手前 30m に設置
  「方面及び距離（案内115）」: 交差点手前 500m・200m・100m に設置
    （エッジ長が短い場合はスキップ）

struct DirectionSign {
    int         nodeId;         // 対応する交差点ノード
    SignType    signType;       // Direction（114） or Distance（115）
    float       arcPos;         // 設置エッジ上の弧長位置
    Array<SignEntry> entries;   // 最大3方面
};

struct SignEntry {
    String  destination;    // 方面名（例: "飯松"）
    float   distanceKm;     // 距離 [km]（Distance 看板のみ）
    ArrowDir arrow;         // Straight / Left / Right / SlantLeft / SlantRight
};
```

## 15. 生成街レビュー基準

実ゲームの Release レンダリングで撮影したスクリーンショットだけをレビュー対象にする。Test 専用シーンや合成画像を合格根拠にしてはならない。

- 道路は地表と自然に接し、地面から浮いて見えないこと
- 道路と建物・土地パッチ・道路標示が不自然に重ならないこと
- 道路標示は `RoadMarkingPlacement` を通じた統一システムで管理し、横断歩道・車線線・停止線などが道路面内に収まること
- 横断歩道は道路進行方向に対して正しい向きで、交差点設備として読める幅と位置を持つこと
- 生活道路の外側に道路部品由来の不要な緑帯を置かないこと
- 地表は旧来のタイル敷きに見えないこと。地表テクスチャ、任意多角形の土地パッチ、畑・水田・砂浜・護岸を用途ごとに分けること
- テクスチャスケールは現実の道路幅・宅地・畑の寸法と釣り合い、近景で巨大に引き伸ばされず、遠景で細かく反復しすぎないこと
- すべての住宅・施設用地は道路に接し、日本の接道義務に反する孤立宅地を作らないこと
- 海沿いの宅地は砂浜または護岸で隔て、海に直接住宅が接しないこと
- 幹線道路と生活道路の階層が地図的に読み取れること

### 用途別地形マテリアル

- 地形メッシュは高さだけでなくゾーン用途を参照し、農地は畑/水田/裸地、住宅地は庭土/砂利、商業・工業は舗装寄りのマテリアルを割り当てる。
- テクスチャのスケールは現実の実寸感を優先し、草・砂・アスファルト・コンクリート・農地ごとに反復周期が不自然でないかをレビュー対象に含める。

### 2026-09-12: アンチエイリアシング・移動物の影・描画負荷

### 2026-09-12: 地形・敷地ストリーミングと区画線
