# 歩行者と乗換の現行仕様

2026-09-17。標準で10,000人の住民を生成する。人数には建物内、徒歩、駅・駐車場での待機、車・電車への乗車中を含む。10,000人全員を常時路上へ並べる設定ではない。初期の接続済み建物が2軒未満なら、建物が増えてから生成する。

## 敷地から敷地への移動

`BuildingAccessIndex` の実在する接道建物を出発地・目的地に使い、建物の道路側の入口から歩き出す。農地、公園、未建築区画は現在の目的地に含めない。目的地へ到着して建物内でしばらく過ごすと、次の移動を選ぶ。

`PedestrianNetwork` は供用中の道路断面の歩道を使い、歩道のない生活道路では路肩を使う。高速道路・自動車専用道路・軌道だけの専用線は徒歩経路に含めない。両側の歩道、交差点の角、道路を横切る区間、敷地入口を別々の接続として持つ。長い道路は60m以下の間隔で区切り、形状は実際のベジェ曲線と歩道の横断位置を参照する。

交差点では近づく車と交差点内の車を確認し、横切る道路が青信号の間も待つ。横断が始まると車側は停止線へ減速する。横断中は遠方でも毎フレーム更新し、遠方用の経過時間を使って車道を一瞬で横切らない。

## 電車への乗換

出発地・目的地から徒歩で到達できる駅を探し、同じ有効なダイヤの停車駅間で乗り換える。徒歩で駅の入口とホームへ進み、実際の列車を待つ。始発列車の生成、途中駅の停車、到着・運行終了のイベントを `TrainManager` から受け取る。行き先の駅に停まる列車だけに乗り、目的駅で降りて目的の敷地へ歩く。

1両80人を標準とし、普通2両は160人、快速4両は320人。満員ならホームで次の列車を待つ。列車に乗っている人は路上へ同時に描かない。運行中の列車は出発時の停車順を保ち、運休・編集は既存の鉄道仕様に従う。長時間列車が来なければ、徒歩経路を再検討する。複数の鉄道路線間の乗継探索、運賃、ホーム上の個人同士の衝突回避はまだ扱わない。

## 駐車場への乗換

駐車場、郊外型コンビニ、郊外型給油所を乗換場所にする。出発敷地から駐車場まで歩き、車道に合流できる空きができたら、`VehicleManager` の実際の車を1台生成して乗る。目的地側の駐車場まで車線・信号・渋滞に従って走り、実到着を受けて降車し、最後の徒歩区間を進む。

駐車場ごとに標準24台の容量、初期12台の共用車在庫を持つ。出発時に在庫を減らし、到着側の駐車枠を予約する。到着で予約を駐車済みに移し、経路不成立では予約を解放する。空車・空き枠・車道への合流余地がない場合は待ち、長く待っても利用できなければ徒歩へ切り替える。

乗車待ちの分だけ通常交通の自動補充に余裕を設けるため、既存の自動補充だけで車両数の上限を埋め続けない。住民の車も全体の車両上限内に含む。個人所有の車、敷地内の駐車操作、駐車料金、駐車場モデル上の駐車台数との同期は現在の対象外。

## 負荷を抑える仕組み

- 視点から500m以内の歩行者は毎フレーム、それ以遠は4シミュレーション秒ごとに位置を更新する。遠方も出発地・目的地・移動手段・乗物のIDを保持する。
- 歩道経路はA*で探索。1更新の探索件数は16、1探索の展開上限は6,000。連結成分で到達不能を早期判定し、直近512経路を再利用する。
- 距離で計算を間引く対象は徒歩区間。車・列車の運行、定員、駐車予約、乗降の状態は近景と遠景で同じ処理を使う。
- 歩道網と施設の接続は道路・建物が変わった場合に更新する。建物索引の更新番号を比較し、同じ件数でも建物の入れ替わりを検知する。変更のない時間帯は作り直さない。
- 歩行者の描画上限は1,000m。100m以内は頭・胴・手足、8種類の歩行姿勢、服10色・体格・肌色の差を表示する。遠方は24三角形の人体へ切り替える。
- メッシュは共有し、毎フレームCPUで頂点を作らない。遠方は256人ごとの変換行列・色をGPUへ渡す。屋内と乗車中は描かない。

停止中は移動と待ち時間を進めない。ネットワーク更新では現在の施設・目的地を照合して経路を作り直す。施設が残っていれば駅・駐車場の待機を保持する。移動中の住民と共用車在庫はセーブ対象外で、ロード後に再生成する。経済の人口統計と個人の住居・職場を一対一に結びつける仕組みは未実装。

## 外部設定と担当コード

値は `App/assets/generation/pedestrians.json`、型・範囲は `GenerationSettings.def`、編集用検査は `schema/pedestrians.schema.json` を使う。反映には再起動する。

| キー | 標準値 | 意味 |
|---|---:|---|
| targetPopulation | 10000 | 住民数。0で無効 |
| routesPerUpdate | 16 | 1更新の徒歩探索数 |
| routeExpansionLimit | 6000 | 1探索の展開上限 |
| nearDistance | 500 | 毎フレーム更新する距離[m] |
| farUpdateSeconds | 4 | 遠方の位置更新間隔[シミュレーション秒] |
| walkSpeed | 1.35 | 歩行速度の基準[m/s]。個人差を加える |
| destinationRestSeconds | 40 | 建物内の滞在時間の基準[秒] |
| maximumTrainWait | 1800 | 列車待ちから徒歩を再検討する時間[秒] |
| maximumParkingWait | 90 | 駐車場待ちから徒歩へ切り替える時間[秒] |
| parkingSpaces | 24 | 駐車場1か所の容量[台] |
| initialParkedCars | 12 | 初期の共用車在庫[台] |
| passengersPerCarriage | 80 | 1両の定員[人] |
| drawDistance | 1000 | 人物の描画上限[m] |
| detailedDrawDistance | 100 | 手足を詳しく描く距離[m] |
| refreshSeconds | 15 | 建物・施設・ダイヤ変更の照合間隔[秒] |

- `PedestrianNetwork`: 歩道と施設の接続、座標計算、探索とキャッシュ。
- `PedestrianManager`: 人口、目的地選択、距離別更新、経路網の更新。
- `PedestrianTrips`: 一人の徒歩経路、横断、敷地への到着。
- `PedestrianTransfers`: 列車の乗降、駐車場の在庫と予約、車の乗降。
- `PedestrianRenderer`: 人物形状、歩行姿勢、色、距離別の一括描画。
- `GameScene`: これらの所有と、車・列車→歩行者の更新順序。

新しい操作パネルは追加しない。診断実行の `playtest_state.json` に人口・徒歩・待機・乗車・完了数、更新時間・描画時間・描画数を記録する。通常プレイで歩行者の個別ログを出さない。

常設検証は `PedestrianTests.cpp`。数値結果と測定条件は [検証記録](../artifacts/pedestrians_20260917/REVIEW.md)。

## 生成要素との整合

自動車を生成しない街では自動車移動を選択しない。明示的な自動車移動指定も徒歩へ戻し、存在しない車を待ち続けない。歩行者自体の生成を外した場合は人口エージェントを作らない。地下断面では地下にいる歩行者のみを描く。
