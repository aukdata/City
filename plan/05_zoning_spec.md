# ゾーニングと街の成長の現行仕様

2026-09-14。初期の街は `SettlementDevelopment`、プレイヤーが塗った空地の成長は `ZoneManager` / `ZoneDevelopment` が担当する。用途、建物、敷地、需要は同じデータを参照する。

## 遊び方

1. 道路を開通させ、Zで「用途と街の開発」を開く。
2. 低層住宅・住宅・商業・工業・農地を選び、道路の隣の空地を塗る。1区画・小ブラシ・大ブラシを選べる。Shift+左ドラッグで矩形指定。
3. 条件の揃った区画は需要に応じ、標準速度で約10〜34秒で完成する。停止中は進まず、×2／×4は開発にも適用する。暦の1日24分は変更しない。
4. パネルで開発中・完成・道路待ち・敷地不足・地形不適を確認する。待機中の区画は道路の開通や周辺の変更後に再判定する。

矩形指定は地面で押し始め、Shiftを押したまま地面で左ボタンを放すと確定する。パネル・HUD・地図上や地面のない位置で放した場合は始点を破棄し、後のクリックやカーソル移動へ持ち越さない。左ボタンを押したままUIを横切って地面へ戻る操作は継続できる。Escや用途ツール終了でも始点を破棄する。

## 用途

| キー | 用途 | 空き区画に建つもの |
|---|---|---|
| 0 | 未指定 | 新規開発を取り消す |
| 1 | 市街化調整 | 新規開発を抑制し現状を保つ |
| 2 | 低層住宅 | 戸建て住宅 |
| 3 | 住宅 | 戸建て・低層マンション |
| 4 | 商業 | 店舗・オフィス |
| 5 | 工業 | 工場 |
| 6 | 農地 | 接道する小規模な畑 |

用途変更は即時・無料。塗り直しや解除によって既存建物を自動撤去しない。建築中に同じ用途を塗り続けても進捗は戻らない。別用途へ変えた空地は新しい用途で評価し直す。

## 立地と敷地

- 16m格子で管理し、隣接チャンクを含めて塗れる。描画上の建物位置は道路に合わせ最大5mだけ補正する。
- 開通済み・既設の生活道路または幹線道路に接道する。工事中、閉鎖、トンネル、高架、高速道路は接道先にしない。
- 道路の実断面・曲線を使い、道路上、交差点への接近部、他の建物、鉄道用地に重なる配置を除外する。鉄道の余白は初期街生成と同じ `ParcelRoadIndex` を使う。
- 建物の中心・四隅・各辺中央で地形を確認する。水面から30cm以下、敷地内の高低差1.2m超、道路との高さの差1.5m超は開発を待機する。
- 道路の外縁と建物の間に余白を置き、入口を道路へ向ける。住宅には庭、商工業には敷地、農地には畑の地表パッチを作る。既存の `UrbanParcel` で隣家との境界を調整する。新築の側だけでなく既存の庭も切り直し、古い庭や塀が新しい家へ入り込まないようにする。
- 田園の大きなほ場・畦道・用排水路の初期配置は [24](24_japanese_urban_morphology.md) と [27](27_roadside_life_spec.md) を参照。

## 需要と成長

需要は0.10〜1.00。住宅は住宅収容人数／人口、商業は人口500人当たり1棟、工業は人口1,200人当たり1棟を基準に計算する。最低需要でも成長が完全に止まらない。需要は待ち時間に反映し、別の生成スコア閾値と掛け合わせない。

標準速度の所要秒数は `10 + 20 × (1 − 需要) + 座標による0〜4秒`。農地の需要は0.5。土地の状態が適している時間だけ進み、建築直前にも配置条件を確認する。

新しい住宅の完成時、住宅容量と建物数を即座に統計へ加え、追加容量の72%を入居人口に反映する。店・工場も統計とその後の需要へ反映する。完成時には既存の完了効果音を鳴らす。月次の収支・幸福度・人口調整は [04](04_gameplay_detail_spec.md) のまま。

## 更新・保存

- プレイヤーが塗った空き区画を待機リストで管理する。全世界のセルを月次に走査して成長を抽選する未接続の処理は廃止した。
- 1回の更新で最大16区画を確認し、同一区画の再確認は約1秒間隔。1回に最大2件を完成させる。大量指定の際は確認を順番に回す。
- セーブ形式4では `global/development.bin` に全チャンクの用途・建物・敷地を保存し、ロード時に正本として復元する。`meta.json` の `zoneDevelopment` には編集セルの記録と待機区画の進捗を保存する。復元後は正本の区画を書き換えず、用途が一致する空き区画だけ進捗を再開する。
- 初期の街に元からある未開発ゾーンを一斉開発する処理、段階的な高層化、自動衰退・解体、許認可や転用費用、地価ヒートマップは現行機能に含めない。

## 建物・外観の正本

占有寸法・住宅容量・モデル選択は `Building.hpp` を参照する。戸建て3人、低層集合住宅20人、中層80人、高層300人、田舎の民家5人。初期生成では都心と郊外のコンビニ・給油所、田舎の民家、公園・公共施設・駐車場も配置する。詳細は [27 沿道の暮らし](27_roadside_life_spec.md)、`App/assets/buildings/REALISTIC_PACK.md`、`App/assets/buildings/commercial/MODEL_CATALOG.md`。

## 検証

`Test/ZoneDevelopmentTests.cpp` で低需要、停止・再開、塗り直し・解除、道路開通、水域・傾斜・道路・隣接建物・鉄道の除外、保存復帰、全用途パネルを検証する。矩形入力の有効操作・UI中断・押下継続は共有本体処理を使う `Test/ZonePaintInputTests.hpp`、チャンク境界をまたぐ矩形塗り・解除・正本スナップショット復帰は `Zoning.RectangleInput.WorldPaintEraseSnapshotRoundTrip` で検証する。本体を使った操作と数値記録は [街の成長のプレイテスト](../artifacts/city_growth_playtest/REVIEW.md)。画像はローカル保存と数値解析で確認し、チャットへ送信しない。

## 自動生成する拠点施設（2026-09-17）

地域中心都市には、一般の沿道建物より先に高層オフィス、市役所、郊外ショッピングモール、病院、学校の用地を確保する。大規模敷地は実際の中心セルを所有者とし、全敷地の重なり検査と隣地分割を行う。市街化調整のセルにも既存の公共施設の敷地を作り、施設下に空き公共緑地を生成しない。街路との接続・選択・撤去・保存は通常建物と共用。[施設仕様](32_urban_facilities.md)を参照。
