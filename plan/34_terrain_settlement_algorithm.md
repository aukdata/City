# 地形・水系・生活圏から街を成長させる生成アルゴリズム

2026-09-17。**設計案**。地形・集落・道路の生成方法を提案する文書であり、以下の全工程を実装済みとは扱わない。現行の河川生成には蛇行・谷壁による抑制・曲線からの水位計算を実装した。その修正は別途[検証記録](../artifacts/terrain_river_design_20260917/REVIEW.md)に記す。地図の配色・文字・描画解像度は対象外。

## 1. 目指す結果

同じ枝分かれを持つ村、地形を無視した三角形の道路網、一定の輪郭で途切れる町を減らす。地形から通行・居住・耕作の条件を共通に求め、道路と家並みがその条件に応じて成長する。格子、直線道路、直線的な河川区間そのものは禁止しない。

| 場所 | 生成結果の方向性 |
|---|---|
| 狭い谷 | 道と川が谷を共有し、家が少し高い沿道に連なる。小さな谷底の耕地が途切れながら続く |
| 広い盆地 | 複数の集落と耕地が分布し、谷口・渡河点を経由する街道が中心町に集まる |
| 丘陵の縁 | 尾根の間へ住宅地・農地が入り込み、道路は造成量を抑えて斜面を回り込む |
| 湾奥・海岸 | 利用できる陸地と内陸への接続がある場所が発展する。街は海岸の帯と背後の谷へ伸びる |
| 城下の周囲 | 旧市街の町割、街道沿いの拡大、独立した村、農地、後代の住宅開発が重なる |

場所の条件は候補の重みを変える。すべての谷口を町、すべての湾を港、すべての平野を格子にする規則にはしない。

## 2. 処理の順序と共通データ

基本地形 → 流域・谷・尾根の形成 → 地形適性と通行回廊 → 集落の候補と生活圏 → 共用する広域道路 → 旧中心からの街路・敷地成長 → 鉄道と現代の拠点 → 農道・農地 → 整合性検査。

道路と街の相互依存は「仮の通行費で候補を選ぶ → 実際の道路が成立するか調べる → 配置と規模を一度補正する」で解く。全時代の人口移動を細かくシミュレーションせず、旧来・鉄道期・現代の3段階で形の履歴を残す。

- `World` の共有する基本地形を正本とする。広域分析は既存64m格子を使い、道路・敷地の最終検査は16m地形と連続曲線で行う。
- `RiverNetwork` が計算する下流ノード・処理順・集水量を再利用し、流域ID、谷の中心、谷幅、合流点、河口を保持する。水系を別モジュールで独立に作り直さない。
- 地形解析は傾斜、局所起伏、水面との比高、通行可能な緩斜面の連続性、耕作適性を作る。集落、道路、農地はこれを共有する。
- 渡河点、峠、谷口は候補グラフの節点。候補グラフは通れる帯を示す補助データで、車両が走るグラフは既存の `RoadNetwork` 一つとする。
- チャンク境界で水系や向き場をリセットしない。外周にも解析用の余白を取り、マップの切断面を架空の海岸と取り違えない。

## 3. 山・谷・平野・海岸を関連づける

### 3.1 河川と谷を同じ骨格から作る

1. 既存の山脈・湾・内陸丘陵の大きな高さ場を初期値にする。
2. くぼみの流出先を求め、下流へ循環しない排水グラフを作る。くぼみを埋める計算用高さを、そのまま完成地面として使わない。
3. 集水量の大きい筋を本流、小さい筋を支流とする。各支流を本流へ接続し、下流方向に河床を低下させる。
4. 河川の周囲を幅のある谷として整形する。幅は集水量だけでなく周囲の起伏にも依存させ、狭い谷と開けた谷底を作り分ける。
5. 谷幅の増加と縦断勾配の減少が重なる谷口では、緩斜面が広がる候補を作る。段丘状の高まりや低湿地も、河道との位置・比高に関連づける。
6. 地形整形後に水の流れを再検査する。河床が逆勾配になる区間は縦断を補正する。必要な掘削が上限を超える場合は別の流出経路や湖としての保持を検討する。

支流の間に残る地形が枝尾根になるため、「丸い山の領域と平原の領域」の境界が、谷と尾根の入り組んだ形になる。谷幅や微地形は空間的に連続した値とし、すべての川の両岸に同幅の帯を貼らない。

これは侵食・堆積の完全な物理計算ではない。河川を骨格に地形を構築する考え方には、[Génevauxほかの河川網による地形生成研究](https://perso.liris.cnrs.fr/eric.galin/Articles/2013-river-networks.pdf)を参考にする。本案の都市配置・費用・調整値は独自のゲーム設計である。

### 3.2 河川の直線化を解消する

- 集水格子は流域と合流先を決める用途に限定し、河道の全頂点を格子に固定しない。
- 長い本支流ごとに連続する距離を持たせる。蛇行の位相・大きさを格子辺やチャンクごとにやり直さない。
- 川幅が広く勾配が緩い区間では側方に動ける余地を増やす。狭い峡谷では周囲の高さを評価し、実際の谷底に沿わせる。
- 蛇行周期と振幅には連続した変化を持たせる。同じ正弦波をすべての川に貼り付けず、地形による抑制と複数の尺度を使う。
- 合流点と河口は共有点とし、支流の変形後も端点・水位を一致させる。近接する別の河道を横切る変形は採用しない。
- **変形した後の流路**で最低地盤高と下流水位を再評価する。水面だけを曲げず、河床、河岸、橋の判定、植生除外を同じ流路から作る。
- 将来は既設の市街地に接する部分だけ直線化・護岸した改修河川を許す。自然河川全体への直線化は避ける。

### 3.3 海岸と平野の上限

海に接する谷の低い部分が入り江、尾根の末端が岬になるよう、沿岸の高さ場と谷を関連づける。河口低地のある開いた海岸、山が迫る入り江の多い海岸を混在させる。独立したノイズで海岸を最後に揺らし、河口と切り離す処理を避ける。

平野の最大面積は従来どおりマップ全体の50%。バイオーム名を付け替えるだけで達成せず、一定範囲の傾斜・起伏も計測する。上限超過時は広域の丘陵配置を先に調整し、水系以降を作る前に確定する。河川整形後の面積も再確認する。谷底の小さな平地や盆地を残し、広い一枚の平原に集中させない。

## 4. 集落の位置・規模を決める

### 4.1 「低い場所」と「住める場所」を分ける

住宅適性は、造成量の小ささ、道路への接続、利用できる乾いた土地の連続性から求める。耕作適性は、水の得やすさ、傾斜、耕せる面積から求める。河道、水面、極端な湿地、急斜面はそのまま住宅候補にしない。

国土地理院は同じ低地の中でも微高地、谷底平野、扇状地、後背低地などを区別している。この区別をゲームの立地指標に翻訳する。災害の実予測モデルとしては扱わない。[地形分類](https://www.gsi.go.jp/bousaichiri/lc_configuration.html)

### 4.2 生活圏で競合させる

候補地は農地のまとまり、谷口、渡河候補、峠道の合流、湾奥と後背地の接続などから得る。位置の採点は次の増分で行う。

`候補の価値 = 新たに支えられる人口・耕地 + 交通・港・行政の機会 − 開設費 − 既存中心と重複する生活圏`

生活圏は直線距離の円ではなく、地形上の移動費用で計算する。同じ盆地では隣の町と競合し、尾根の反対側では直線距離が近くても別の生活圏になる。価値の高い候補から採用し、採用するたびに未充足の需要を減らす。人口・耕地を複数の中心へ重複配分しない。

城・寺社・港などの成立理由と、現在の都市規模は別の属性にする。少量のシード依存の差で歴史的な選択肢を持たせるが、地形的に成立しない候補を乱数だけで採らない。

大都市は最大4。村・町の生成率1/4、外周1kmの中心地除外を保持する。新しい候補数が変わるので「率」と完成時の件数を別々に記録し、後段で間引いた分を補充して密度を元に戻さない。ニュータウンは追加の独立都市ではなく既存都市の地区として扱う。

道路が成立しない候補には、同じ生活圏内での移動・縮小・不採用を行う。中心だけ存在してアクセスできない街を確定しない。

## 5. 広域道路を共用する

### 5.1 地形回廊を先に比較する

谷沿いの両岸、峠越え、谷口、渡河点、海岸の利用可能な帯を粗い候補グラフへ載せる。平野には自由な接続候補も作る。谷沿いの道は水面上ではなく、道路幅と造成範囲が収まる側岸へ置く。

中心間の直線距離で接続順を決め切らず、回廊ごとの概算建設費と実際のアクセス需要を比較する。まず必要な接続を成立させ、その後、往来の改善効果が新道の費用を上回る候補を追加する。道の共有で遠回りが過大になる場合には短絡路が選ばれる。

### 5.2 ネットワークと1本の線形で目的を分ける

ネットワーク全体の評価は、各項を共通の比較単位に変換して使う。

`J(N) = 新設部分の建設費 + 維持費の換算値 + Σ(区間需要 × 実際の所要時間の換算値)`

採用した中心への接続を制約とする。建設費は重複する道路を一度だけ数え、既存の使用可能な道路に合流する場合の増分を評価する。既存道路にも移動時間がかかり、存在するだけで自由に横断・合流できるとはしない。

1本の新設区間を具体化する線形探索では、既存の `RoadAlignment` と `RoadConstructionCost` を共用する。費用の標準値は以下を維持する。

- 地上: 延長あたり1。
- 掘割・許容内の切盛土: 延長あたり8。
- 高架: 延長あたり `64 + 16h + 16(exp(h/12) − 1 − h/12)`。hは地面からの高さ[m]。
- トンネル: 延長あたり128に、連続長L[m]に対する `400×32×(exp(L/400) − 1 − L/400)` を加算。

設定の正本は `assets/generation/roads.json`。費用は通貨ではなく地上道路を基準にした比較値。トンネル長の罰則をエッジ分割でリセットしない。

### 5.3 九十九折りを探索結果にする

探索状態は位置・標高・進行方向・連続トンネル長を持つ。道路種別の最大勾配、最小半径、道路幅、構造物の離隔を満たす曲線だけを展開する。接続後の曲線も再検査する。

例えば標高差100m、最大勾配6%なら、必要な水平延長は少なくとも約1.67km。直線500mの急坂は不適格になり、長い斜面の迂回や折り返しと、高価な橋・トンネルを比較する。曲がること自体への報酬は付けない。

終点から一時的に遠ざかる探索を許し、峠や斜面の広さに合わせて探索領域を広げる。複数の粗い回廊を試し、細かい探索の方向候補にも連続した折り返しが表現できる解像度を用意する。厳しい制約を満たせなければ街全体を持ち上げず、接続案を見直す。

有限回の粗密探索・局所改善なので、全域での数学的な最適解は保証しない。「見つからなかった」と「到達不可能」を区別する。鉄道は同じ路盤グラフに載せ、鉄道用の厳しい勾配・曲率・駅の直線長を使う。

## 6. 道路と家並みを少しずつ成長させる

完成した長方形の街路を置いてから地形で切る方法を、地形に成立する街区を増やす方法へ置き換える。

1. 旧中心と広域街道の沿道に、初期の街区・敷地を置く。
2. 既存街路の延伸、既存道路への接続、背後の土地へ入る短い道を候補として列挙する。
3. 各候補に対し、追加で接道できる土地の面積と用途需要、既存経路の改善量、造成・道路費を計算する。
4. `増える敷地とアクセスの価値 − 道路費 − 宅地造成費 − 失う農地等の価値` が大きいものから採る。
5. 街路を追加するたびに前面の敷地を確保し、残りの人口・用途予算を減らす。近接した道には接続候補を出すが、地形制約を無視した接続はしない。
6. 予算を使い切るか、価値のある延伸先がなくなったら止める。

格子の旧市街や計画住宅地では地区内に方向の選好を持たせる。ただし街道、川、段丘の縁を越えて同じ軸を無制限に押し通さない。地区ごとの軸は周辺の道路にも引き継ぎ、すべての地区が無関係に回転した格子になるのを避ける。

### 密度はアクセスから連続的に決める

沿道の候補地xに対し、住宅や店舗の密度を次のような連続関数で求める。

`D(x) = sigmoid(b + Σ a_i exp(−T_i(x)/τ_i) − 造成負担 − 湿潤負担 + 小さな連続変動)`

T_iは旧中心、駅、生活中心等までの道に沿った所要時間。a_iは拠点の強さ。敷地の適性と街区単位の空地を別に扱うため、個々の建物を無関係な乱数で欠落させた斑点にはしない。

中心から離れるほど住宅・商店・農地が混在し、街道沿いは遠くまで伸び、アクセスしにくい尾根や低地が空地として残る。外縁を行政界や計画矩形で切らない。急崖や海岸による明瞭な境界は自然な制約として残す。

駅や港は利用可能な土地と交通の条件を確認してから現代の成長核にする。東京系の複数拠点、京都系の旧市街の格子、地方都市の駅前と旧中心など、既存の都市類型は核の関係と成長の選好として使い、完成形の輪郭にはしない。

## 7. 農道・農地を街の外側へ連続させる

- 最初に耕作に向く土地のまとまりを求め、実際の道路沿いに田舎の家の候補を置く。農地の中心から架空の独立道路を生やさない。
- 既存道路から耕地に向けた進入路と、農地群同士の連絡路を生成する。最小化するのは延長・造成・給水や排水の横断・不要な既存道との重複。
- 道路、川、斜面の方向から地区内の向きを求める。町に近い整った土地は街の道路軸を継ぎ、谷では等高線と細長い耕地の方向が強くなる。
- 道と水路を境界として、その隙間をほ場に分割する。土地の形に応じて矩形、台形、曲がった多角形を許す。基準になる方向が近隣で連続するようにする。
- 耕作可能な土地の中では、村や田舎の家から通いやすい場所ほど農地が多く、離れると薄くする。住宅・水域・道路は農地から除く。
- 農地の全範囲が田舎の家から500m以内になる条件を維持する。農道は完成した通常道路として登録する。
- 近い既存道への接続と、最短路が直線距離の3倍以上となる村間の短絡処理を最後の整合性検査として残す。追加後は実際の道路グラフで改善を確認する。

## 8. 処理時間と実装の分担

64m格子は約105万点。広域分析を一度行い、後段で同じ高さ・最寄り河川・流域を繰り返し探さない。詳細探索は採用候補の周囲だけに絞る。全候補間の総当たりや大量の地質・人口エージェントは用いない。

- `World` / `RiverNetwork`: 地形と水系の生成・共有。河床整形後の値を正本にする。
- 地形解析の小さなモジュール: 谷・峠・低地・適性の計算。描画や敷地の所有は持たない。
- `SettlementPlacement`: 適性と生活圏による位置・規模。半径ごとの独立配置から改める。
- `MapGenerator` / `RoadAlignment`: 接続候補の選択と具体的な合法線形。別の道路グラフは作らない。
- `DistrictRoads` / `SettlementFringe` / `SettlementDevelopment`: 共有した沿道成長候補を使い、街路・敷地・家並みの境界を一致させる。
- `AgriculturalLayout`: 実際の道路と耕作条件から農道とほ場を生成する。

パラメータは既存の `assets/generation/` へ集約する。地形・適性・成長・探索予算の意味で分類し、同じ制約や費用を各工程へ重複定義しない。乱数系列は工程ごとに分離し、樹木を無効にしても川や町の位置が変わらないようにする。

広域の補正は少数回に制限し、道路の候補数・展開数にも予算を設ける。これらの処理時間は未計測であり、速度改善は実測してから報告する。

- [x] 現行河川の蛇行と地形適合を改善し、合流・水位・近接水路を検査する（22シード。流域から地形全体を形成する工程は未実装）。
- [ ] 集落の候補と生活圏を地形解析へ接続し、中心の位置・規模を改める。
- [ ] 谷・峠・渡河点を利用した広域道路の候補探索と道路の共有を導入する。
- [ ] 街路・沿道敷地の成長と連続的な外縁密度へ置き換える。
- [ ] 都市類型・駅・港・ニュータウンを成長核として接続する。
- [ ] 農道・農地の向きと区画を周辺の街道・水系へ合わせる。
- [ ] 同一条件の複数シードで、生成時間・成立率・景観指標・従来制約を検証する。

検証は「曲線が増えた」だけを合格条件にしない。人工の狭い谷・広い低地・Y字合流・河口・峠・急斜面で、完成形が地形条件に反応するかを確かめる。平地の合理的な直線道路まで曲げていないことも確認する。

| 検査 | 条件 |
|---|---|
| 河川 | 逆勾配・循環・非接続の交差がない。川床が水面下。合流点の座標・水位が一致。平野と峡谷で蛇行量が変わる |
