# プロシージャル生成仕様書

## 概要

ゲーム開始時にシード値と地形タイプからマップを生成する。
生成物は「既成市街地（旧道＋集落）をもつ平成初期の日本の小さな町」。

---

## 1. 生成パラメータ（開始画面）

| パラメータ | 入力方式 | 説明 |
|-----------|---------|------|
| シード値 | 整数入力 or ランダムボタン | 乱数の種、同じシードなら同じマップ |
| 地形タイプ | 4択ボタン | 下記参照 |

## 2. 地形タイプ

### タイプA: 山間盆地（さんかんぼんち）
```
・四方を山に囲まれた盆地
・中央に川が流れ、川沿いに平野が広がる
・旧街道は川に沿って縦断する
・バイパス候補: 山の切り通し or 盆地外周の迂回路
```
```
[山] [山] [山] [山]
[山] [平] [平] [山]
[山] [平] [川] [山]  ← 旧道は川沿いを縦断
[山] [平] [平] [山]
[山] [山] [山] [山]
```

### タイプB: 沿岸平野（えんがんへいや）
```
・片側が海、反対側が山地
・海岸線沿いに旧街道、港町が核になっている
・漁港・観光地の要素あり
・バイパス候補: 山際の新道 or 海岸埋立
```
```
〜〜〜〜〜〜〜〜〜〜  ← 海
[港] [平] [平] [平]
[平] [平] [平] [丘]  ← 旧道は海岸線に沿う
[丘] [丘] [山] [山]
```

### タイプC: 河川扇状地（かせんせんじょうち）
```
・山から流れ出る複数の川が合流する扇状地
・川の分岐・合流が多く、橋が重要インフラになる
・水害・冠水イベントが起きやすい
・バイパス候補: 川の上流側の高台ルート
```
```
    [山]
   /    \
[川]   [川]   ← 複数の川筋
  \    /
  [合流] [平野]
```

### タイプD: 丘陵台地（きゅうりょうだいち）
```
・緩やかな丘が連続する地形
・丘の上に集落、谷に田んぼが広がる
・旧道は丘の稜線に沿う（昔からの道）
・バイパス候補: 谷を貫く新道（トンネル or 高架）
```
```
[丘] [谷] [丘] [谷]
[集] [田] [集] [田]  ← 集落は丘の上
[丘] [谷] [丘] [谷]
```

## 3. 地形生成アルゴリズム

### Step 1: 高さマップ生成

```
1. Perlinノイズ（多重オクターブ）で基本高さマップを生成
   - オクターブ数: 6
   - 周波数: 地形タイプにより調整
   - 振幅減衰: 0.5

2. 地形タイプ別マスクを乗算
   - 山間盆地: 中央を凹ませるラジアルグラデーション
   - 沿岸平野: 片側を低く傾けるランプ関数
   - 河川扇状地: 中央から広がる扇型の傾斜
   - 丘陵台地: 中周波ノイズを強調

3. 高さ値を離散化
   - h < 0.1  → 水域（海・湖）
   - h < 0.2  → 低地（氾濫原・河川敷）
   - h < 0.5  → 平野
   - h < 0.7  → 丘陵
   - h >= 0.7 → 山地
```

### Step 2: 河川生成

```
1. 山地の高点から水を流す（流水シミュレーション）
   - 各セルから最も低い隣接セルへ流れる
   - 流量が閾値を超えたセルを河川としてマーク

2. 河川の浸食処理
   - 河川セルの高さをわずかに下げる
   - 河川沿いに低地（氾濫原）を形成

3. 河川幅
   - 流量に応じて1〜4セル幅
```

### Step 3: 地表種別の決定

| 高さ | 勾配 | 水域 | → 地表種別 |
|------|------|------|-----------|
| 低地 | - | あり | 水域（河川・湖） |
| 低地 | 緩 | なし | 水田・湿地 |
| 平野 | 緩 | なし | 農地・草地 |
| 平野〜丘 | 緩 | なし | 宅地適地 |
| 丘〜山 | 急 | なし | 林地・山林 |
| 山 | 急 | なし | 岩地 |

## 4. 集落配置と形成計画（実装済み）

根拠となる調査と各類型の違いは [日本の街の成り立ちと生成モデル](24_japanese_urban_morphology.md) を参照。

1. 地形適性を評価し、最小間隔2,800 mのポアソン配置で核を選ぶ。
2. `SettlementKind` は地域中心都市・地方町・農村という規模だけを表す。地域中心は20 km間隔を基本とし、近接する都市や周囲の集落数から地方町の候補を決める。
3. 海岸距離・方向、標高、起伏、近隣都市、シードから、城下・街道・門前・港・市場・工業・計画・農村の起源を選ぶ。農村は集村・散村・谷筋に分ける。
4. `UrbanMorphology::Plan` に街区軸、矩形の範囲、旧中心、駅、公共用地、工業用地を保持する。宿場・港は細長く、工業・計画地区は大街区とする。
5. 全街路の地形検査後、必要なら計画全体を縮小し、駅を街区内へ再配置する。道路が成立しない場所は沿道型に切り替える。
6. 地区内の通りは共通の直交軸で通し、中心からの距離に応じて通り単位で間隔を変える。交差点ごとの座標ノイズは加えない。
7. 農村では既存地域道路を残し、道路接線に対する支線・裏道と実際の接道位置を生成する。

都市の町割と旧道の接続では、矩形から100 m外側で既存の地域道路を実曲線上で分割する。内側を新しい街路へ置換し、同じ辺の入口へつなぐ。近接した入口はまとめ、公共用地に向かう無用な短い枝道を除く。形状だけでなく路線・車線・RoadPartも更新する。

## 5. 旧道ネットワーク生成

集落間を繋ぐ旧道を **3層の分岐構造** で生成する。

### Layer 1: 幹線街道（RegionalCity間チェーン）

```
1. RegionalCity 地区のみで Prim's MST を計算
2. MST上の最長パス（diameter）を求める → メイン街道チェーン
   - BFS 2回で tree diameter を抽出
3. diameter チェーン上の連続ペアを A* で接続
   - RoadType: Arterial（市街地外は2車線・歩道なし）
4. diameter に含まれない RegionalCity → MST上の親（diameter上の RegionalCity）へ枝線接続
```

### Layer 2: 地方道（LocalTown → 幹線への分岐）

```
1. 各 LocalTown 地区に対して、最寄りの幹線街道中間ノードを検索
   - 空間ハッシュ（バケットサイズ200m）で O(1) 検索
2. 最寄りノードから LocalTown へ A* パスファインディング
   - forbiddenGoalDirs に幹線の接線方向を設定 → 自然な Y字分岐
   - RoadType: Arterial（2車線）
3. 幹線から5km以上離れた LocalTown → 最寄りの接続済み LocalTown へ接続
   - RoadType: LocalRoad（2車線）
```

### Layer 3: 集落道（RuralSettlement → 最寄り道路ノード）

```
1. Layer 1+2 の全中間ノードで空間ハッシュを構築
2. 各 RuralSettlement 地区に対して:
   - 距離 < 300m → 「街道沿い」扱い（道路生成不要）
   - 距離 >= 300m → 分岐道路を A* で生成
     - RoadType: LocalRoad（中央線なしの双方向生活道路）
     - forbiddenGoalDirs で Y字分岐を誘導
3. 全 RuralSettlement 集落を必ず接続する（孤立集落は禁止）
```

### A* 経路探索（全Layer共通）

```
コスト = 距離 × 勾配ペナルティ × 地形ペナルティ

勾配ペナルティ:
  slope < 5%  → ×1.0（平坦）
  slope < 15% → ×2.0（緩斜面）
  slope < 30% → ×5.0（急斜面）
  slope >= 30%→ ×20.0（ほぼ通過不可）

地形ペナルティ:
  水域（h < 0）→ ×10.0

Y字分岐メカニズム:
  1. 分岐道路は既存の中間ノード（約120m間隔）に接続
  2. forbiddenGoalDirs で幹線接線方向へのアプローチを回避
  3. 最終的な道路形状から実交点を求め、共有区間を統合して分岐位置を確定
```

### 街道の種別

```
RegionalCity ↔ RegionalCity（メインチェーン・枝線）→ Arterial（2車線、都市内の主要軸のみ4車線）
幹線ノード → LocalTown                            → Arterial（2車線）
LocalTown → LocalTown（遠距離接続）                → LocalRoad（中央線なしの双方向生活道路）
道路ノード → RuralSettlement                             → LocalRoad（中央線なしの双方向生活道路）
```

### Step 4: 橋の自動生成

```
街道が河川を横断する箇所に橋を自動生成
橋の仕様:
  川幅 < 10m  → 単純橋（コンクリート）
  川幅 < 30m  → 桁橋
  川幅 >= 30m → プレートガーダー橋
```

## 6. 初期建物と駅の配置（実装済み）

道路・土地利用・建物は同じ `UrbanMorphology::Plan` を参照する。旧市街、駅前、住宅、計画住宅、産業、公共用地、農地を区別する。

- 旧市街の商業軸は店舗主体、駅前は店舗・オフィス・集合住宅を混在させる。駅と旧市街の間は通りに沿う商業軸でつなぐ。
- 一般住宅地は規模に応じた戸建て・集合住宅の構成とし、計画住宅地は中層住宅を増やす。農村は農家と農地を組み合わせ、散村は実際の道路アクセス先へ住宅を寄せる。
- 産業は大きな連続用地へ集中させる。公共用地は道路と通常の建物を避け、現在は緑地として確保する。城・寺社専用の建物は未実装。
- 間口と密度は地区により変更する。建物・敷地の相互干渉、全道路への侵入、地形、水際、接道距離を共通検査する。
- 建物生成を道路の矩形範囲と一致させ、別の円形マスクで街区の四隅を空地にしない。公共用地や地形不適地は意図的な非建築地として扱う。

### 初期鉄道設定

地域中心都市と計画開発地区の `plan.station` に実際の駅を生成する。先頭4集落という制限を廃止し、道路・商業核と駅位置を共有する。駅間の線形は既存の順次直線接続、ダイヤは600秒間隔・停車30秒の簡易設定を維持する。地形を考慮した広域鉄道網の再設計は未実装。

## 7. 初期ゾーン自動設定（実装済み）

`Plan::sample` の地区判定を道路・建物と共有する。旧市街・駅前は商業、産業用地は工業、公共用地は調整区域、住宅地は規模に応じた住居／低層住居、外縁の平坦地は農業とする。標高・勾配も検査する。従来の中心から300 m／600 mという同心円の一律割当ては使用しない。

## 8. 初期交通状態（Phase 5）

生成直後から渋滞が発生している状態にする。

```
初期車両配置:
  各道路区間に「飽和率」を設定
    幹線国道: 70〜90%（すでに混んでいる）
    県道:     40〜60%
    生活道路: 10〜30%

車両は初期位置から目的地（ランダムな集落）へ向けて走行開始
→ ゲーム開始直後から幹線に車が集中して渋滞が発生
```

## 9. 生成の再現性・バリエーション

```
同一シード値 + 同一地形タイプ → 完全に同じマップを生成
シード値が違うと:
  ・地形の形状が変わる
  ・集落の位置・数が変わる
  ・街道のルートが変わる

地形タイプが違うと（同一シードでも）:
  ・地形の骨格が変わる（山の位置・川の流れ）
  ・集落種別の傾向が変わる（沿岸なら港町、盆地なら城下町的）
```

## 10. チャンクとの統合

```
生成データはチャンク単位で保持:
  各チャンクは生成時に以下を受け取る:
    ・高さマップ（HeightMap）のそのチャンク分
    ・道路グラフのうちそのチャンクに属するエッジ・ノード
    ・建物リスト
    ・ゾーンマップ（初期ゾーンは Phase 6 で自動設定）

遅延生成:
  カメラが接近したチャンクのみ詳細メッシュを生成
  遠距離チャンクは高さマップのみ保持（LOD）
```

## 11. 生成フロー全体

`地形 → 集落の規模・起源 → 旧中心・駅・産業・公共用地 → 地域道路 → 地形に適合する地区内道路 → 接続・重複整理 → 水域横断の橋梁化 → 地形・道路を避けた鉄道 → 共通計画による用途・敷地・建物 → 制約検査 → 交通初期化`

生成時間、入口接続数、街区軸のずれ、用途別建物数、接道・干渉・看板除外違反を `DebugLog` に記録する。処理時間を固定値として扱わず、実ワールドごとに測定する。

### 2026-09-12: 接道配置と生成整合性

- 沿道候補は道路の弧長16mごとに採り、交差点のcutoffからさらに6m離した利用可能区間へ均等に配置する。セルは保存先に使い、実際の配置は道路上の投影点と法線から求める。
- 建物の実座標・回転・種別寸法で隣接建物との分離軸判定を行う。チャンク境界をまたぐ隣接セルも調べる。
- 道路・鉄道の帯を4m刻みで64m空間バケットに登録し、接道先以外の道路への侵入も禁止する。配置領域の四隅が標高2.6m未満、または高低差1.2m超なら配置しない。
- 街道接続には元ノードを再利用し、同一座標の作業ノード間を結ぶ長さ0の接続辺を作らない。
- 初期配置・補充配置・生成後検証で同じ道路干渉判定を使用する。拒否理由別件数と処理時間をDebugLogに記録する。

### 2026-09-12: 街区内部の宅地区分

住宅の裏庭、側面・背面の低い塀、非対称な樹冠の庭木、商業・駐車場の後方作業用地と実寸駐車枠を生成する。敷地の外接矩形に装飾を置かず、分割後の多角形への包含と境界からの距離を検査する。塀・樹冠・駐車枠は道路・交差点ポリゴンへの干渉も検査する。地表は従来どおり道路を差し引いて地形三角形に追従する。

新規生成の宅地はPolygon::Validateの結果を理由別に記録し、無効な多角形があれば生成検査を不合格とする。既存セーブの外周は頂点の向きを補正し、敷地輪郭を維持する。両側の道路角度144通りとチャンク境界の回帰テストを常設する。

### 道路階層・建物密度・外観

道路の幅・歩道・線・速度は `StreetProfile.hpp` の役割別断面を使用する。具体値は `24_japanese_urban_morphology.md` §5 を参照。駅前・旧市街・住宅・産業という用途別の密度と構成は `GameScene.cpp` で共有計画を参照する。以前の「城下町全域に同じ幹線間隔」「中心からの距離だけで高層化」という設定は置き換えた。

中高層建物の舗装敷地、雑居ビルの外階段・看板・室外機・屋上設備、低層店舗の外観バリエーション、農村の田畑・屋敷林、山際の森林は既存資産を利用する。

### 2026-09-12: 重複する幹線・接続道路の整理

後処理は角度補正、2本接続部の平滑化、城下町の直線化、実交点の分割、共有区間の統合、再交差判定の順とする。交差判定後に制御点を一律回転・直線化しない。

`consolidateOverlappingRoads` は道路断面の範囲内で重なる供用中の道路を対象とし、途中の接続先・枝道・路線を引き継ぐ。長い並走区間は共有する1本の道路へ統合し、実際に分かれる位置へ分岐点を移す。計画や建設中の道路、十分に離れた並行道路は対象外。ID順に処理し、同じデータの再修復で変化しないことを回帰テストする。

### 町割の検証

農村の沿道型を除く全起源の町割に直線化・整合性検査を適用する。最後の直線化は地区内で軸に沿う道路だけを対象とし、市街地外の曲線を変更しない。新規生成の実測と回帰テストは `artifacts/urban_morphology/REVIEW.md` を参照。

### 2026-09-13: 街区内路地・空街区の禁止・水域横断

- 町割の辺長が88m以上、短辺56m以上の閉じた区画には、対向する道路を結ぶ幅4.4mの路地を加える。歩道・中央線は設けず、側溝と路肩を付ける。両端は既存道路を分割して接続し、隣の街区と接続ノードを共有する。
- 計画段階で街区内部を24m間隔、道路を線上で検査し、標高3.2m未満の計画は縮小する。沿岸の道路だけが成立して内側に建物を置けない町割を避ける。
- 最終道路グラフから実際の閉じた街区を列挙する。都市計画内の各街区に実建物があることを確認し、空なら道路境界に沿って6m間隔で補充候補を探す。農地・駐車場のみの区画は充足とみなさない。公共用地には公共施設を配置する。
- 通常配置の最大地形差は1.2m、空街区の低層補充のみ2.5mまで許容し、最高地盤に合わせた基礎・擁壁を描く。道路・鉄道・隣接建物への侵入、水際、接道制約は緩和しない。空街区が残れば生成検査を不合格とする。
- 最終道路形状の車道・路肩を6m間隔で水域検査する。水域付近を48m以下に分割し、必要部分を海面上6m以上の橋とする。共有端点から取付勾配を伝播し、岸の盛上がりは制御点の局所上昇で越える。地域全体を一律に高架化しない。これは新規生成の処理であり、ロード時に保存済み道路を再分割しない。
- 測定結果と再現コマンド: `../artifacts/city_expansion/REVIEW.md`。
