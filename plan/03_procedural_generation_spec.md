# プロシージャル生成仕様書

2026-09-16更新：[生成設定・LOD・大量交通](28_generation_assets_lod_traffic.md)を参照。生成値の正本は `App/assets/generation/`。通常車は建物前で発着し、全体上限12,000台、画面外でも車列を更新する。

## 1. 生成の前提（現行実装）

シードから65,536m四方の地域を生成する。海岸・山脈・平野を先に決め、河川、都市と周辺の村、交通、建物と農地を重ねる。同じシードと生成規則なら同じ基本地形になる。既存セーブの地形を移行する処理は設けない。

従来の「4種類から地形タイプを選ぶ」構想は[旧案](unused/03_terrain_proposal_before_2026-09.md)へ分離した。現行の広域地形は、以下の連続した生成で構成する。

## 2. 海岸・周縁の山地・起伏のある平野（2026-09-16）

`World::setGenerationParams` で海岸の向き、湾の位置、山並み、中央の地形をシードから確定する。全チャンクが同じ座標系を参照する。

- **低地と内陸の丘陵・谷を組み合わせる。** 主山地を内陸側の周縁、副山地を片側の側縁へ寄せ、向き・位置・幅と途切れる谷を変える。外周全体を一律の壁で囲まず、山麓・平野・海岸への開口を残す。街の座標を中央へ強制移動せず、実際に残る乾いた緩斜面から従来の立地評価で選ぶ。
- 中央の地形は平野56%、山12%、湖13%、大湾19%を設計上の選択確率とする。山や湾があっても必ず中央全域を塞ぐわけではない。中央の山は局所的な山体、大湾は外海から入り込む形にする。湖は低い盆地を掘り下げ、既存の水面0m・流入河川で表現する。高所の湖の個別水位・流出管理までは対象外。
- 海岸は主湾・副湾の大きな形に、数km規模の岬と数百m単位の凹凸を重ねる。海岸座標を2次元で変形し、小さな入り江が湾へ分かれる形と岬をつくる。正方形の全外周を沈めたり、長いほぼ直線の1本だけで海陸を区切ったりしない。
- 平野は約4.6kmと約1.5kmの空間スケールを持つ起伏を重ねる。内陸へ一様に上がる傾斜を従来の1/5へ弱め、波打つ低地・浅い凹地が内側にも残るようにする。細部ノイズは控えめにし、道路・農地の勾配制約を変えずに宅地と耕地が成立する程度の起伏とする。
- 主山地・副山地の基準高は1,850 / 1,500m。山が重なる場所を単純に足して過大な標高にせず、谷・峠・稜線の蛇行で変化をつける。小さな検証マップでは地形の振幅を縮小する。
- 海岸の標高は水面へ連続してつなぐ。基本地形の高さ・振幅と、閉じた湖の領域からバイオームを決める。高さ生成と別の無関係なノイズで海域を判定しない。

地形の分類は[国土地理院「海の作用による地形」](https://www.gsi.go.jp/kikaku/tenkei_umi)、[同「大地形」](https://www.gsi.go.jp/kikaku/tenkei_daichikei.html)を参考にする。物理的な地殻変動・海進の計算ではなく、ゲーム用の決定的な地形関数である。寸法・確率は日本全国の統計値ではなく設計値。

常設検証 `Terrain.RegionalComposition` は20シードで中央の適地率、外周の海・山の割合、平野の局所高低差、外海につながる海岸線の屈曲、中央の山・湾・湖の存在を測る。平野系バイオームの合計はマップの50%以下に制限する。残る海・山・丘陵の比率はシードで変える。詳しい定義・比較結果は [検証記録](../artifacts/terrain_composition/REVIEW.md)。

広域地形の64m格子事前計算、平野上限、山村、生成要素の選択、畦道の接続と村間の迂回解消は [33 生成と地下表示](33_generation_and_underground.md) を参照。

## 3. 河川と地表

基本地形を `RiverNetwork` が流域として処理し、流量に応じた河道を切り込む。川の水位は場所ごとに異なる。道路と集落は海面だけでなくこの水位も使い、水中への住宅生成を避ける。河川・切盛土・構造物の詳細は[26 地形と交通](26_landscape_transport_spec.md)。

平坦な乾いた低地を都市・農地の候補とし、山腹には林地、谷底には水路と耕地を配置する。地形の見た目だけで宅地と決めず、集落配置時に水面からの余裕と周辺の勾配・農地の余地を検査する。

## 4. 集落配置と形成計画（実装済み）

根拠となる調査と各類型の違いは [日本の街の成り立ちと生成モデル](24_japanese_urban_morphology.md) を参照。

1. `SettlementPlacement` で地形候補を順位付けし、周囲の耕地の広がりから中心町と農村を選ぶ。
2. `SettlementKind` は地域中心都市・地方町・農村という規模を表す。地域中心都市は1マップ最大4個、20 km間隔を基準に、農業立地を持つ地方町、周辺の村を配置する。中心への地形上の往来費用で村の生活圏と間隔を変える。都市から6 km以内でも農村を一律昇格させない。寸法・費用場は [都市形態仕様 §8](24_japanese_urban_morphology.md#8-中心町と周辺集落の生活圏2026-09-15)。
3. 海岸距離・方向、標高、起伏、近隣都市、シードから、城下・街道・門前・港・市場・工業・計画・農村の起源を選ぶ。農村は集村・散村・谷筋に分ける。
4. `UrbanMorphology::Plan` に街区軸、矩形の範囲、旧中心、駅、公共用地、工業用地を保持する。宿場・港は細長く、工業・計画地区は大街区とする。
5. 全街路の地形検査後、必要なら計画全体を縮小し、駅を街区内へ再配置する。道路が成立しない場所は沿道型に切り替える。
6. 格子型地区の通りは共通の直交軸で通し、中心からの距離に応じて通り単位で間隔を変える。交差点ごとの座標ノイズは加えない。
7. 農村と地方町の宿場・門前では既存地域道路を残し、道路接線に対する支線・裏道と実際の接道位置を生成する。
8. 都市の外周から住宅街を段階的に延ばし、外側ほど道路と住宅を疎らにする。町割に沿う既存道路から地形に沿った農道を伸ばし、その間に不整形の田畑を配置する。集落から離れるほど密度を下げ、全区画を田舎の家から500m以内に保つ。詳細は24章§7。

都市の町割と旧道の接続では、矩形から100 m外側で既存の地域道路を実曲線上で分割する。内側を新しい街路へ置換し、同じ辺の入口へつなぐ。近接した入口はまとめ、公共用地に向かう無用な短い枝道を除く。形状だけでなく路線・車線・RoadPartも更新する。

## 5. 旧道ネットワーク生成

集落間を繋ぐ旧道を **3層の分岐構造** で生成する。

### Layer 1: 幹線街道（RegionalCity間チェーン）

```
1. RegionalCity 地区のみで Prim's MST を計算
2. MST上の最長パス（diameter）を求める → メイン街道チェーン
   - BFS 2回で tree diameter を抽出
3. diameter チェーン上の連続ペアを A* で接続
   - RoadType: Arterial（市街地外は2車線・歩道なし）
4. diameter に含まれない RegionalCity → MST上の親（diameter上の RegionalCity）へ枝線接続
```

### Layer 2: 地方道（LocalTown → 幹線への分岐）

```
1. 各 LocalTown 地区に対して、最寄りの幹線街道中間ノードを検索
   - 空間ハッシュ（バケットサイズ200m）で O(1) 検索
2. 最寄りノードから LocalTown へ A* パスファインディング
   - forbiddenGoalDirs に幹線の接線方向を設定 → 自然な Y字分岐
   - RoadType: Arterial（2車線）
3. 幹線から5km以上離れた LocalTown → 最寄りの接続済み LocalTown へ接続
   - RoadType: LocalRoad（2車線）
```

### Layer 3: 集落道（RuralSettlement → 最寄り道路ノード）

```
1. Layer 1+2 の中間ノードで空間ハッシュを構築。接続のない点は道路として選ばない
2. RuralSettlement を中心への往来費用順に処理し、距離と地形回廊の方向から接続先道路を選ぶ:
   - 距離 < 300m → 「街道沿い」扱い（道路生成不要）
   - 距離 >= 300m → 分岐道路を A* で生成
     - RoadType: LocalRoad（中央線なしの双方向生活道路）
     - forbiddenGoalDirs で Y字分岐を誘導
3. 未接続の地区は再接続を試みる。後段の勾配・曲率制約を満たせない経路を無理に建設しない（成立率の課題はISSUE参照）
```

### 地形回廊と制約付き線形探索（全Layer共通）

粗い地形回廊も道路種別の勾配と `RoadConstructionCost` を参照する。距離に対して許容勾配を超える高さから切土・盛土・構造物の費用を見積もり、水域では水面上6mを満たす橋の高さを使う。既存道路との重複や接続端の鋭角には追加のペナルティを持つ。鉄道の粗い探索は別の係数を維持する。

最終的な道路の比較は実際の曲線を約8m間隔で評価して行う。地上1、掘割・許容範囲の盛土8、高架64＋地盤から路面までの高さ[m]×16＋高さの指数罰則、トンネル128＋連続延長の指数罰則。縦断・九十九折り・曲率制約と探索上限の正本は [27 道路線形](27_roadside_life_spec.md#道路の勾配と曲線半径)。

分岐道路は既存の中間ノードを入口に使い、`forbiddenGoalDirs` で鋭いアプローチを避ける。最後に実曲線上の交点を分割し、共有区間を統合する。

### 街道の種別

```
RegionalCity ↔ RegionalCity（メインチェーン・枝線）→ Arterial（2車線、都市内の主要軸のみ4車線）
幹線ノード → LocalTown                            → Arterial（2車線）
LocalTown → LocalTown（遠距離接続）                → LocalRoad（中央線なしの双方向生活道路）
道路ノード → RuralSettlement                             → LocalRoad（中央線なしの双方向生活道路）
```

### Step 4: 橋の自動生成

```
街道が河川を横断する箇所に橋を自動生成
橋の仕様:
  川幅 < 10m  → 単純橋（コンクリート）
  川幅 < 30m  → 桁橋
  川幅 >= 30m → プレートガーダー橋
```

## 6. 鉄道・駅・車庫

駅は集落計画の駅前核と道路アクセスを共有する。地形・道路との関係、駅と車庫の線形制約、初期ダイヤと編集は [10 鉄道](10_railway_spec.md) と [26 地形と交通](26_landscape_transport_spec.md) を参照する。古い直線接続・600秒固定間隔の構想を現行仕様として使用しない。

## 7. 初期ゾーン自動設定（実装済み）

`Plan::sample` の地区判定を道路・建物と共有する。旧市街・駅前は商業、産業用地は工業、公共用地は調整区域、住宅地は規模に応じた住居／低層住居、外縁の平坦地は農業とする。標高・勾配も検査する。従来の中心から300 m／600 mという同心円の一律割当ては使用しない。

## 8. 初期交通と補充

人口と商業・工業の需要に応じて車両を生成し、供用状態・車間・目的地への到達可能性を確認する。到着後の補充は `VehiclePopulation` が担当する。道路ごとの固定飽和率で最初から車両を詰める構想は用いない。車種・出現距離・上限は [27 自動交通](27_roadside_life_spec.md#自動生成する交通) を正本とする。

## 9. 再現性・バリエーション

同一シードと同じ生成規則で基本地形・集落計画を再現する。シード変更で海岸の向き、湾の形、山脈と谷、集落の位置・規模・起源が変わる。固定候補の配置、町割・建物の生成、チャンク境界の高さ一致を常設テストで確認する。以前の地形タイプ選択は旧案へ移した。

## 10. チャンクとの統合

高さ・ゾーン・建物・敷地と農地はチャンク単位で保持する。道路と鉄道の接続は別のネットワークで管理する。地割はチャンクごとに作り直さず、共通の世界座標から各チャンクへ所属させる。カメラに近い領域で詳細メッシュを用意し、遠方はLODと非同期生成で扱う。

## 11. 生成フロー全体

`地形 → 集落の規模・起源 → 旧中心・駅・産業・公共用地 → 地域道路 → 地形に適合する地区内道路 → 接続・重複整理 → 水域の区間分割 → 勾配・曲率と費用による経路調整 → 橋の取り付け・土工 → 地形・道路を避けた鉄道 → 共通計画による用途・敷地・建物 → 制約検査 → 交通初期化`

生成時間、入口接続数、街区軸のずれ、用途別建物数、接道・干渉・看板除外違反を `DebugLog` に記録する。処理時間を固定値として扱わず、実ワールドごとに測定する。

### 2026-09-12: 接道配置と生成整合性

- 沿道候補は道路の弧長16mごとに採り、交差点のcutoffからさらに6m離した利用可能区間へ均等に配置する。セルは保存先に使い、実際の配置は道路上の投影点と法線から求める。
- 建物の実座標・回転・種別寸法で隣接建物との分離軸判定を行う。チャンク境界をまたぐ隣接セルも調べる。
- 道路・鉄道の帯を4m刻みで64m空間バケットに登録し、接道先以外の道路への侵入も禁止する。配置領域の四隅が標高2.6m未満、または高低差1.2m超なら配置しない。
- 街道接続には元ノードを再利用し、同一座標の作業ノード間を結ぶ長さ0の接続辺を作らない。
- 初期配置・補充配置・生成後検証で同じ道路干渉判定を使用する。拒否理由別件数と処理時間をDebugLogに記録する。

### 2026-09-12: 街区内部の宅地区分

住宅の裏庭、側面・背面の低い塀、非対称な樹冠の庭木、商業・駐車場の後方作業用地と実寸駐車枠を生成する。敷地の外接矩形に装飾を置かず、分割後の多角形への包含と境界からの距離を検査する。塀・樹冠・駐車枠は道路・交差点ポリゴンへの干渉も検査する。地表は従来どおり道路を差し引いて地形三角形に追従する。

新規生成の宅地はPolygon::Validateの結果を理由別に記録し、無効な多角形があれば生成検査を不合格とする。既存セーブの外周は頂点の向きを補正し、敷地輪郭を維持する。両側の道路角度144通りとチャンク境界の回帰テストを常設する。

### 道路階層・建物密度・外観

道路の幅・歩道・線・速度は `StreetProfile.hpp` の役割別断面を使用する。具体値は `24_japanese_urban_morphology.md` §5 を参照。駅前・旧市街・住宅・産業という用途別の密度と構成は `SettlementDevelopment.cpp` で共有計画を参照する。以前の「城下町全域に同じ幹線間隔」「中心からの距離だけで高層化」という設定は置き換えた。

中高層建物の舗装敷地、雑居ビルの外階段・看板・室外機・屋上設備、低層店舗の外観バリエーション、農村の田畑・屋敷林、山際の森林は既存資産を利用する。

### 2026-09-12: 重複する幹線・接続道路の整理

後処理は角度補正、2本接続部の平滑化、城下町の直線化、実交点の分割、共有区間の統合、再交差判定の順とする。交差判定後に制御点を一律回転・直線化しない。

`consolidateOverlappingRoads` は道路断面の範囲内で重なる供用中の道路を対象とし、途中の接続先・枝道・路線を引き継ぐ。長い並走区間は共有する1本の道路へ統合し、実際に分かれる位置へ分岐点を移す。計画や建設中の道路、十分に離れた並行道路は対象外。ID順に処理し、同じデータの再修復で変化しないことを回帰テストする。

### 町割の検証

農村の沿道型を除く全起源の町割に直線化・整合性検査を適用する。最後の直線化は地区内で軸に沿う道路だけを対象とし、市街地外の曲線を変更しない。新規生成の実測と回帰テストは `artifacts/urban_morphology/REVIEW.md` を参照。

### 2026-09-13: 街区内路地・空街区の禁止・水域横断

- 町割の辺長が88m以上、短辺56m以上の閉じた区画には、対向する道路を結ぶ幅4.4mの路地を加える。歩道・中央線は設けず、側溝と路肩を付ける。両端は既存道路を分割して接続し、隣の街区と接続ノードを共有する。
- 計画段階で街区内部を24m間隔、道路を線上で検査し、標高3.2m未満の計画は縮小する。沿岸の道路だけが成立して内側に建物を置けない町割を避ける。
- 最終道路グラフから実際の閉じた街区を列挙する。都市計画内の各街区に実建物があることを確認し、空なら道路境界に沿って6m間隔で補充候補を探す。農地・駐車場のみの区画は充足とみなさない。公共用地には公共施設を配置する。
- 通常配置の最大地形差は1.2m、空街区の低層補充のみ2.5mまで許容し、最高地盤に合わせた基礎・擁壁を描く。道路・鉄道・隣接建物への侵入、水際、接道制約は緩和しない。空街区が残れば生成検査を不合格とする。
- 最終道路形状の車道・路肩を6m間隔で水域検査する。水域付近を縦断確定前に48m以下に分割し、川底下のトンネルを除いて必要部分を現地の水面上6m以上の橋とする。両方向の岸と近接する元の取付端を使い、道路種別の勾配以内へ整える。遠くの高い地盤を次々に高さの発生源にしない。地域全体を一律に高架化しない。これは新規生成の処理であり、ロード時に保存済み道路を再分割しない。
