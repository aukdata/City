# 車両種別仕様書

日本の道路交通法を簡略化した車両種別の定義。
道路への通行規制・IDMパラメータ・特殊挙動に影響する。

---

## 1. 車両種別一覧

```cpp
enum class VehicleType : uint8 {
    PassengerCar,  // 普通乗用車
    KeiCar,        // 軽自動車
    Moped,         // 原動機付自転車（原付）
    LightVehicle,  // 軽車両（自転車・荷車等）
    Bus,           // 路線バス
    SmallTruck,    // 小型トラック（積載2t以下）
    LargeTruck,    // 大型トラック（積載4t以上）
    Emergency,     // 緊急車両（警察・消防・救急）
};
```

## 4. 通行可否

| 種別 | 生活道路 | 県道 | 国道 | バイパス | 高速道路 |
|------|---------|------|------|---------|---------|
| 普通乗用車 | ○ | ○ | ○ | ○ | ○ |
| 軽自動車 | ○ | ○ | ○ | ○ | ○ |
| 原付 | ○ | ○ | ○ | **×** | **×** |
| 軽車両 | ○ | △ | △ | **×** | **×** |
| バス | △ | ○ | ○ | ○ | ○ |
| 小型トラック | △ | ○ | ○ | ○ | ○ |
| 大型トラック | **×** | ○ | ○ | ○ | ○ |
| 緊急車両 | ○ | ○ | ○ | ○ | ○ |

> **×** = 通行不可。経路探索でそのエッジのコストを ∞ にする
> **△** = 幅員制限あり（幅3m未満の道路は不可）

### 原付・軽車両の通行制限の根拠

```
バイパス・高速道路は「自動車専用道路」に指定されるケースが多く、
原動機付自転車（第一種）・軽車両は通行不可（道交法 第16条）

バイパスでも「一般道」扱いなら原付は通行可だが、
本仕様ではバイパス以上は自動車専用道路として扱う
```

## 5. 車線使用ルール

### キープレフト（道交法第20条）

3車線以上の道路では重い・遅い車種は左車線を走る。

```cpp
float laneUsagePenalty(VehicleType vtype, int laneIdx, int totalOpenLanes) {
    // 原付・軽車両: 最左車線のみ
    if (vtype == Moped || vtype == LightVehicle) {
        if (laneIdx > 0) return 1e9f;   // 実質禁止
    }
    // 大型・バス: 右寄りほどコスト増
    if (vtype == LargeTruck || vtype == Bus) {
        if (laneIdx > 0) return kHeavyRightPenalty * laneIdx;
    }
    // 追越車線（最右）: 追い越し時のみ（全車種）
    if (laneIdx == totalOpenLanes - 1) return kOvertakingLanePenalty;
    return 0.0f;
}
```

### 原付・軽車両の右折制限（二段階右折）

3車線以上の交差点では原付・軽車両は二段階右折が必要。

```
二段階右折の経路:
  ① 最左車線を直進して交差点を渡る
  ② 停止線で一時停止
  ③ 横断方向の信号が青になったら直進

→ 経路探索では「右折 LaneConnection」コストに大きなペナルティを加える
   代わりに「直進×2回」を迂回路として選ぶよう誘導
   const float kTwoStageRightTurnPenalty = 60.0f;  // 秒
```

## 6. 特殊挙動

### バス

```
・固定路線を走る（ダイクストラではなく路線データに従う）
・バス停に接近すると減速・左寄せ・停車（停車時間: 15〜30ゲーム秒）
・停車中は後続車が追い越し or 待機
・バスとして登録されていない車体は通常の大型車としてダイクストラ適用
```

バス停のデータ構造:
```cpp
struct BusStop {
    int   id;
    int   roadEdgeId;   // 紐づく RoadEdge
    float arcPos;       // エッジ上の位置 [m]
    int   laneIndex;    // 停車する車線インデックス（最左 open lane）
    String name;
};
```

バス停への紐づけ（配置時）:
  マップ上でクリックした位置に最も近い RoadEdge を検索
  → その arcPos に BusStop を登録

バス車両の停車ロジック:
  Vehicle.type == Bus かつ ダイヤに当該バス停が含まれる場合:
  → バス停まで距離 30m に到達: IDM の v_des を 0 に設定（減速開始）
  → arcPos がバス停 arcPos ± 2m に入ったとき state = WaitingBusStop
  → 停車時間（15〜30ゲーム秒）経過後、次の目的地へ発車

バスと道路 congestion:
  バスは通常の車両エージェントとして LaneNode を占有するため、
  congestion 計算（laneVehicles の台数）に自動的に含まれる。
  路線データ駆動であっても Vehicle として走行するため別途加算は不要。

### 大型トラック

```
・生活道路に進入不可
・RoadEdge の weightLimit を超える橋・高架は通行不可
  weightLimit: float  // t 単位。0 = 制限なし
・急勾配（slope > 8%）で速度低下
  speed_factor = max(0.3, 1.0 - (slope - 0.05) * 3.0)
・深夜に発生比率が高い（物流の夜間集中を再現）
```

### 危険物積載車のトンネル通行制限

```
大型トラックのうち「危険物積載」フラグが立っている車両は、
トンネル長が 5000m を超える区間を通行不可とする。

struct Vehicle {
    ...
    bool hazardous;  // 危険物積載フラグ
};

経路探索での処理:
  GraphEdge がトンネル区間（TunnelEdge）の場合:
    if (vehicle.hazardous && tunnel.length > 5000.0f)
        edge cost = infinity  // 経路探索でその区間を回避

発生比率:
  大型トラックの約20%を危険物積載車とする（ゾーン・時間帯は大型トラックと同じ）

視覚表現:
  危険物積載車は荷台に「危」標識（橙地に黒文字）を表示（近接時のみ）
```

> 根拠: 道路法施行令 第19条の3・危険物積載車両のトンネル通行制限（5000m超）

### 軽車両（自転車等）

```
・最左車線のみ走行可
・路肩・自転車帯があればそちらを優先
・交差点での信号は守る（ただし歩行者信号にも従う）
・速度が遅いため後続の乗用車が詰まる原因になる
  → 自転車が多い生活道路は実効容量が下がる
```

### 緊急車両（サイレン時）

```
[緊急車両自身の挙動]
  ・信号を無視して通過可能（赤信号でも進入）
  ・制限速度を超えた走行が可能
  ・逆走・対向車線使用が可能
  ・経路探索コストを全辺 × 0.1 で計算（最速ルート優先）

[周囲車両の挙動]
  緊急車両がサイレンを鳴らしながら接近したとき:
  ・接近を検知した車両は左車線へ寄せて減速・停車
  ・交差点の手前にいる車両は信号が青でも交差点に進入しない
    （緊急車両が通過するまで停止線で待機）
  ・緊急車両が通過した後、通常走行に復帰

[検知ロジック]
  半径 R_detect 以内に緊急車両が存在し、かつ自分の走行方向と
  衝突しうる経路上にある場合に「待機」状態に入る

  const float R_detect = 100.0f;  // m

  bool shouldYield(Vehicle& self, const Vehicle& emv) {
      if (!emv.sirenActive) return false;
      float dist = distance(self.position, emv.position);
      if (dist > R_detect) return false;
      // 緊急車両の進行方向が自分の交差点に向かっているか判定
      return isApproachingMyIntersection(emv, self.nextNode);
  }
```

> 信号を「強制青」にしないことで、緊急車両通過中は交差点の全方向が停止し、
> 実際に近い「交差点封鎖」の状態が自然に再現される

## 10. 車両ライフサイクル

### 発生レート

TrafficManager が毎ゲーム分、アクティブチャンク内の発生エッジから車両を生成する。

発生レート = チャンク内の総人口 × ratePerCapita × 時間帯スケール / (チャンク数 × 60)

```cpp
const float kRatePerCapita = 0.002f;  // 人あたり・分あたりの発生台数
```

発生レートは §7 の時間帯スケールで乗算する。

### 生成位置

発生エッジ: 交差点ノードに隣接する RoadEdge のうち、車線が open なもの
arcPos: 0.0（エッジ始端）から発生し、すぐに走行開始

生成できない条件:
  ・発生位置の arcPos に先行車両が存在する（gapToLead < s0）
  → 次フレームに再試行

### 目的地の選択

目的地エッジ = 以下の重み付き抽選で決定：

```
weight(edge) = zoneAttractivenessWeight(edge.chunkId)
             × distancePenalty(dist(origin, edge))

zoneAttractivenessWeight:
  商業地域: 3.0
  工業地域: 2.0
  住居地域: 1.0
  その他:   0.5

distancePenalty = exp(-dist / 3000.0f)  // 遠いほど低確率
```

目的地が決まったら dijkstra() で経路探索を実行。

### 目的地到達後の挙動

```
目的地エッジの終端 arcPos に到達:
  → 50% の確率で消滅（トリップ完了）
  → 50% の確率で新しい目的地を選択して走行継続

駐車場エッジに到達した場合:
  → 消滅（駐車場の congestion を +1 して周辺道路の congestion 計算に影響）
```

## 詳細車両モデル（2026-09-11）

近距離ではPassengerCarにsedan、KeiCarにkei_wagon、Busにcity_bus、EmergencyにID偶奇でpatrol_car/fire_engineを割り当てる。assets/vehicles/からモデルと拡散色を初回読み込みしてキャッシュする。+X前方・Y上・メートル単位とし、既存のpitch/yaw変換を共用。シルエットも同じモデルを使用。遠景とその他の車種は従来の簡易表示。交通挙動・衝突寸法・出動ロジックは変更しない。
