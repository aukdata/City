# 案内標識（方面系）仕様書

## 概要

道路標識のうち **方面及び距離（106）** と **方面及び方向（108の2）** を独立系統 `GuideSign` として実装する。
既存の `RoadSignPlacement`（規制・逆三角・円形）とは板サイズ可変・複数エントリ保持という点で構造が異なるため、データ・モジュール・描画を分離する。

国道番号標識（118、おにぎり）は単一数値表示のため、既存の `RoadSignType::NationalRoute` のまま運用する。

### 現行実装（2026-04）

- `GuideSignPlacement` は `RoadEdge` 内ではなく `RoadNetwork` の独立配列で管理する
  - `id`, `parentEdgeId`, `sourceNodeId` を持つ
- 板面内容は `GuideSignEntry` ではなく `Array<SignElement>` で保持する
  - `Text`, `DestName`, `DestDistance`, `Arrow`, `ArrowNoHead`, `RouteNumber`
- `widthOverride`, `heightOverride`, `bgColor`, `showReading` を個別指定できる
- 自動生成標識は保存せず、手動編集標識のみ `global/guide_signs.json` に保存する
- エッジパネル上の簡易編集に加え、`guide_sign_editor` で WYSIWYG 編集できる
- 108の2 は丁字路時に `ArrowNoHead` を使う
- 国道番号アイコンは板面要素として重ね描きできる
- ポールは `assets/signs/guide/guide_pole.obj` と `guide_pole.json` の組で描画する

## 1. データモデル

### 1.1 GuideSignKind

```cpp
enum class GuideSignKind : uint8
{
    DirectionDistance,   ///< 106: 矢印 + [地名, 距離km] × 1〜3
    DirectionArrow,      ///< 108の2: [地名, 矢印方向] × 2〜3（交差点手前）
};
```

Phase 2 以降で `Advance`（108 予告）、`LaneDirection`（107）を追加可。

### 1.2 GuideSignEntry

```cpp
struct GuideSignEntry
{
    String place;        ///< 行先地名
    float  km    = 0;    ///< 距離 [km]（DirectionDistance のみ）
    uint8  arrow = 0;    ///< 矢印方向（DirectionArrow のみ） 0=直進 1=左 2=右
};
```

### 1.3 GuideSignPlacement

```cpp
struct GuideSignPlacement
{
    GuideSignKind       kind;
    int                 nodeEndId     = -1;  ///< edge.nodeA / nodeB のいずれか（向き基準）
    float               arcOffset     = 0;   ///< nodeEnd 端から内側への距離 [m]
    float               lateralOffset = 0;   ///< 道路中心からの横方向 [m]（A→B 進行方向で負=左）
    float               poleHeight    = 3.5f;///< ポール高さ [m]
    bool                autoGenerated = true;
    Array<GuideSignEntry> entries;
};
```

### 1.4 RoadEdge への追加

```cpp
struct RoadEdge {
    ...
    Array<GuideSignPlacement> guideSigns;
};
```

## 2. 地名解決

### 2.1 NamedDestination レジストリ

`RoadNetwork` に以下を追加:

```cpp
struct NamedDestination {
    int    nodeId;
    String name;
    uint8  tier;   ///< 0=Urban 1=Suburbs 2=Rural（優先度）
};

class RoadNetwork {
    ...
    Array<NamedDestination> m_namedDestinations;
    HashTable<int, int>     m_destByNode;  ///< nodeId → namedDestinations index（高速逆引き）

    int  addNamedDestination(int nodeId, const String& name, uint8 tier);
    void clearNamedDestinations();
    const String* getDestinationName(int nodeId) const;
    const Array<NamedDestination>& namedDestinations() const;
};
```

### 2.2 充填タイミング

- **新規生成**: `GameScene::placeAllSettlements()` 後、全道路生成後に各 Settlement の中心位置に最も近い RoadNode を見つけて登録
- **ロード**: `loadGame()` で districts.json 読み込み後、同じロジックで再登録
- 永続化しない（districts.json + roads.bin から再構築可能）

### 2.3 到達地名探索

```cpp
/// エッジ端 (edgeId, nodeEndId) から外向きに BFS で最大 N 件の名称付き目的地を集める
Array<GuideSignEntry> GuideSign::resolveDestinations(
    const RoadNetwork& network, int edgeId, int startOutNodeId, int maxCount);
```

- **探索方式**: 単純 BFS。エッジ長を累積し、名称付きノードに達した時点で `(name, km)` を記録
- **重複除去**: 同一地名は最短距離のみ採用
- **並び**: 近い順
- **tier 優先**: 同距離帯（差 < 2km）では Urban > Suburbs > Rural
- **打ち切り**: 深度エッジ数 > 30 または累積距離 > 50 km

### 2.4 自動 / 手動

- Phase 1: 常に自動推論で `entries` を埋める。`autoGenerated=true`
- Phase 3: UI から手動上書き時は `autoGenerated=false` とし、セーブ時も `entries` を永続化

## 3. 自動配置

### 3.1 Phase 1: DirectionDistance（106）

- 対象: `edge.length >= 200m` のエッジ
- 各ノード端について 1 本配置:
  - `arcOffset = 150m`（ノード端カットオフ基準で内側）
  - 進行方向の右側に lateralOffset（規制標識と同じ Roadbed 基準 + `kSideMargin_m`）
- 複数エントリ: `resolveDestinations(edge, 反対側ノード, 3)` で取得

### 3.2 Phase 2: DirectionArrow（108の2）

- 対象: `node.attachments.size() >= 3` の交差点に向かうエッジの手前
- `arcOffset = 300m`（短ければ `length * 0.7`）
- 各出口エッジについて `resolveDestinations(…, 1)` で最短名称を取得
- 矢印方向は `classifyTurnByAngles` で Left/Straight/Right に丸める

### 3.3 再計算

`RoadNetwork::recomputeAllAutoGuideSigns()` を新設。以下のタイミングで実行:

- 新規生成後 / ロード後 / エッジ追加・削除・分割・マージ後
- NamedDestination 再構築後

既存の `recomputeAllAutoSigns()` と同構造。

## 4. 描画

### 4.1 メッシュ

- **ポール**: 既存 `RoadSign::CreatePoleMesh(h)` を流用
- **看板**: プロシージャル平面四角形（w, h 可変）を `GuideSign::CreateBoardMesh(w, h)` で生成
  - ローカル座標: 原点 = 看板中心、X 右・Y 上・Z 前面法線

### 4.2 看板寸法ルール

- エントリ行数 N、1 行高 = 0.35m、パディング = 0.15m
- 高さ: `h = 0.15*2 + 0.35*N`
- 幅: `w = max(最長地名幅, 2.0m)`（地名幅の推定は簡易に「文字数 * 0.45m」）

### 4.3 テクスチャ合成

- `RoadRenderer::m_guideSignTexCache : HashTable<uint64, RenderTexture>`
- キー: `kind` + `entries` のハッシュ
- 合成内容:
  - 背景: 青 `ColorF{ 0.05, 0.20, 0.55 }`、白縁 4px
  - 各エントリ: 和文（大）+ ローマ字（小）+ 距離 or 矢印
  - フォント: 既存 `FontAsset(Asset::*)` から日本語対応フォントを流用（Arial + 日本語）
- 既存 `m_routeSignTexCache`（国道おにぎり号数合成）と同じ仕組み

### 4.4 描画タイミング

- `RoadRenderer::render()` 内、エッジごとの `drawSigns(...)` の直後に `drawGuideSigns(...)`
- キャッシュ: `m_guideSignCache[edge.id] : Array<GuideSignDraw>`（既存 `m_signCache` と同型）

## 5. 永続化（セーブ形式 v10）

`RoadBinary::kVersion = 10`。v7/v8/v9 互換読み込み維持。

RoadEdge レコード末尾に追加:

```
uint32 guideSignCount
for each guideSign:
    uint8  kind
    int32  nodeEndId
    float  arcOffset
    float  lateralOffset
    float  poleHeight
    uint8  autoGenerated
    uint32 entryCount
    for each entry:
        uint16 placeLen + UTF-8 bytes
        float  km
        uint8  arrow
```

v9 以前ではこのブロックを読まず、`guideSigns` は空配列で初期化。
v10 書き込み時、`autoGenerated=true` の guideSigns は**書き出さない**（ロード後に `recomputeAllAutoGuideSigns()` で再生成）。これは既存の `signs` と同じ扱い方針。
