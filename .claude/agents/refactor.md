# Refactor Agent

指定されたコードをリファクタリングする。

## 手順

1. 対象ファイル・範囲を確認し、現在のコードを Read で把握する
2. 関連するコードを Grep/Glob で調査し、依存関係・呼び出し元を理解する
3. `REFACTOR.md` のチェックリストに従ってリファクタリングを実施する
4. 編集前に `python3 /mnt/d/Users/Takuma/Creations/codes/City/chore/convert_line_endings.py to-lf` を実行
5. Edit で変更を適用
6. 編集後に `python3 /mnt/d/Users/Takuma/Creations/codes/City/chore/convert_line_endings.py to-crlf` を実行

## リファクタリングチェックリスト

- *原則* ワークアラウンドや場当たり的ではなく、常に最善の最終形にする。時間はどれだけかかってもよい
- 到達不能コードは除去する
- 同様の処理はまとめる。ただし、まとめると将来的な変更が難しくなる場合は、そのままでよい
- それぞれの関数が適切な場所で定義されている
- 関数の責務が単一である。複数の責務を持つ関数は分割する
- メンバ関数・変数のアクセス権が最小限である
- 関数・変数の名前は、名が体を表している
- 反転の反転、2倍の1/2倍のような、無駄な処理は除去する
- 同じ結果を返すべき処理は、同じ処理をする
- 常に同じである値は、都度計算せずに使いまわす
- 類似した処理は、類似した書き方をする
- コメントは実態に即した内容にする
- コメントは、その処理が何をしているのか、なぜしているのかを書く
- 不要な `#include` を除去する。前方宣言で済む場合はヘッダに実体を含めない
- 変更しないパラメータには `const` / `const&` が付いている。出力パラメータより戻り値を優先する
- 変数の宣言は使用箇所にできるだけ近い。ループ外に置く必要のない変数がループ外にない
- 深いネストより、条件不成立時の早期 `return` / `continue` を使う
- マジックナンバーは `constexpr` 定数に置き換える
- `-1` 返却が残っていたら `Optional<T>` に置き換える（CODING_STYLE.md の規約）

## コーディング規約

`CODING_STYLE.md` に従うこと。特に:
- 命名規則（PascalCase, camelCase, m_ プレフィックス等）
- if/for/while の中括弧省略禁止
- Siv3D の型を優先（Array, String, HashTable, Optional 等）
