# コマンド編集と見えている建物の選択

2026-10-02 UTC。Linuxの実アプリと常設テストで検証。低スペック向け最適化とは別の、元の操作性改善。

## コマンド入力のBackspace

修正前、実キーで `/abcdef` を入力後、短いBackspace1回と1.5秒の長押しのどちらでも文字列が変わらなかった。常設の実CommandPaletteを使う `Input.PaletteBufferedBackspaceRegression` も失敗した。

原因となり得る入力経路を確認した。パレットはSiv3Dの生テキスト中の制御文字に削除を任せていたが、LinuxのXIMなし経路ではBackspaceをUnicode入力へ渡さない。今回のライブXIM状態自体は計測していないため、その分岐を断定しない。

生テキストに削除文字がない場合だけ、バッファ済みBackspace/Deleteを補う小さなヘルパーを追加。生テキストとキーの両方が来たときは二重削除しない。ネイティブの長押しリピートを優先し、IME編集中には補わない。短い複数回入力の回数を保持する変更は編集キーに限定。

修正後の実アプリ:
- `/abcdef` → 短い1回 → `/abcde`
- さらに短い3回 → `/ab`
- さらに1.5秒保持 → 空文字
- 編集中のカメラ位置・ゲーム停止状態は維持

`Input.` 8件、`Comprehensive.PaletteOwnsBufferedInput` 1件成功。Unicode、境界、二重削除防止、IME、リピート、イベント再生防止を含む。Windows実機での入力検証は未実施。Ctrl+Aは既存パレットに選択範囲モデルがなく、今回追加していない。Deleteの文字列中間位置はヘルパーのテストで確認し、パレットへ新しいカーソル移動機能は追加していない。

## 屋根の後ろの信号を選んでしまう

修正前、画面上の小店舗の屋根をクリックすると建物ではなく信号N12873の設定パネルが開いた。地面へのレイ交点から10m以内の信号を、建物の直接レイ交差より先に選んでいた。

現行の優先順位を抽出した同じ判定ヘルパーに幾何fixtureを与え、屋根・隠れた標識・屋根に直接当たっていない近傍信号の3assertionが失敗することを確認。これはprivate GameSceneメソッド全体をそのまま実行した再現ではなく、現行優先順位の抽出テスト。修正後のGameSceneはこのヘルパーを使用する。

建物へレイが当たる場合だけ、描画と同じ信号・標識メッシュの交差距離と比較。手前の見える信号の選択、建物に遮られない地面上の10m以内の簡単選択は保持。

実アプリの同じ保存、同じカメラ、同じクリックを通常描画と低スペック描画の両方で確認:
- ウィンドウ内座標 `(758,558)`
- eye `(24179.3510,131.4831,23858.2519)`
- ray `(0.3211798,-0.7683021,-0.5536745)`
- 建物Chunk(23,23), Cell(41,14)、交差距離120.2585449m
- 近傍信号N12873にはメッシュ直接交差なし
- 両描画モードとも建物が黄色で強調され、建物パネルが開いた

`WorldSelection.` 3件成功。通常／低スペックの選択レイは同じで、低解像度化による座標ずれではなかった。候補・交差距離のログはplaytest時のみ。
