# 描画性能の改善（2026-10-06）

## 対象と変更

- 建物の形状生成をGPU資源に触れないCPUワーカーへ移した。対象チャンクと隣接8チャンクの高さ・建物・道路切削・施設をコピーし、epoch/revisionが一致した完成結果だけを公開する。GPU転送は建物・地形それぞれ約2msの時間枠で分割する。個々のGPU呼び出しの所要時間は厳密には上限化できない。
- 建物の準備中と遠景では、位置・回転・寸法を維持した材質別の代理形状を使用する。中距離では結合したモデルLODへ早めに切り替え、遠景の細かな設備を省略する。地域全体の代理建物をロード時に用意するので、未訪問の地域も表示できる。
- 遠方の道路と交差点をチャンク・舗装属性・テクスチャ・色ごとに結合し、個別の詳細キャッシュ生成を避ける。元の道路幅、地形追従、設計高、切欠き、描画距離を維持する。撤去前の端点も保持して交差点の残像を防ぐ。編集時は該当バッチを無効化し、通常描画へ戻しながら一度に1チャンクを再結合する。
- 視点距離1800m超では微細な影を省略する。近景の影と太陽光による陰影は維持する。
- 初期道路切削・表示範囲・地域地形、建物テクスチャ、地形材質、HUDと地名の文字、標識テクスチャ、影シェーダーをロード中に準備する。移動時の仮地形はポリゴン切削を行わない16×16格子にする。
- HousingCapacityCacheは全建物グリッドの巡回を止め、Chunk::contentRevisionが変わったチャンクだけ集計する。生成・保存復元・成長・敷設撤去・編集はmarkMeshDirtyを通してrevisionを更新する。

## 比較条件

Release / seed 42 / 現行形式4の検証用セーブ `refactoring_20261006` / 1920×1080 / VSync有効 / 13時 / 時間停止 / 車両0台。カメラのyaw=-0.7、pitch=0.72、距離650・3000・6000・12000mの順。各視点480フレーム以上を取得し、最初の240フレームを除いた次の240フレームを比較する。これは全キャッシュの準備完了を保証する条件ではない。

変更前は `05c4688` に解像度指定・詳細計測のみを追加した本体（ビルド `20261006-152336-build-40iu4fnc`）。CPUの描画時間と実フレーム間隔を分け、フレーム間隔はScene::DeltaTimeの100ms上限を受けないStopwatchで測定する。平均FPSは平均フレーム間隔の逆数とする。GPU計測は3Dパスのみで、画面転送・UI・待機を含まない。

最終の広域3視点では100ms超のCPU描画は0回。初回近景表示には106.403msの停止が1回残る。フレーム間隔のP95は27.32〜28.02msで、平均60FPSでも全フレームが16.7ms以内になるわけではない。詳細は `baseline/summary.json` と `final/summary.json`。

全326テストが最終ビルドで合格し、City/TestのReleaseビルドは警告・エラー0。GPUで遠景道路の表示・撤去後の消失、建物の非同期公開・生成途中の撤去を検証した。住宅キャッシュは未変更チャンクを再走査しないことと、描画フラグが解除された後も変更された睡眠チャンクを集計できることを検証した。

720サンプルの固定飛行はCPU平均10.974→7.580ms、P95 18.558→15.715ms、最大1492.438→25.092ms。最終走行は40ms超0回で、従来のHUD区間1488ms・影区間205msの停止はこの経路では再発しなかった。原因を単一の変更に断定せず、変更全体の同条件計測として扱う。streamingのframeMs列は従来のScene::DeltaTime（上限100ms）なので、長い停止の比較にはCPU時間を使う。

6段階の地点移動はCPU平均26.957→14.638ms、P95 34.565→25.212ms、最大6293.734→180.887ms。初回徒歩切り替えのフェーズ最大は404.191→69.378ms、別地点への移動は112.224→21.441msだった。待機フレームを含むため、前1865・後1489サンプルと件数は異なる。初回表示以外のフェーズの最大は70ms未満だった。

中間版の地点移動には道路設備・地形区間で約1秒の停止があった。文字と道路の表示範囲の事前準備を加えた直近2回の完走では再発していないが、原因をこの変更だけに断定しない。遅い処理の道路ID・チャンク・区間を20ms超で記録する診断を残した。

最終の広域計測は最終Cityビルドで実施。連続移動と地点移動の計測後には、1800m超の遠景で霧の時刻更新を維持する修正だけを加えた。これらの移動経路は近距離であり、変更した遠景の早期returnには入らない。ビルドの対応はvalidation.jsonに記録する。

## 再実行

先に `python chore/run_check.py build --target City` を成功させ、City/Testが終了している状態で実行する。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File artifacts/performance_20261006/wide_probe.ps1 final -SaveName refactoring_20261006
python artifacts/performance_20261006/summarize.py baseline final
python chore/run_check.py playtest --mode streaming --seed 42 --timeout 1800
python chore/run_check.py playtest --mode navigation --seed 42 --timeout 1800
```

検証用セーブがない環境では `-SaveName ""` で新規生成する。その場合は今回の保存データとの厳密な同一条件比較にはならない。生CSV・ログはこのディレクトリの各実行ラベルおよび `artifacts/local_runs/checks/` にローカル保存する。画像は会話へ送信しない。

## 検証と限界

最終チェックの記録は `validation.json` に保存する。最初の全テストではSaveTransaction.RoundTripのディレクトリ移動がアクセス拒否になり325/326件合格だった。保存実装を変更しない単独再実行は合格し、原因は断定しない。

今回のFPS比較はこのセーブ・解像度・視点・時間停止条件に限る。任意の街、走行中の交通量、全ての編集操作で60FPSを保証するものではない。
