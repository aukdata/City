# 通常ゲームへの河川統合（2026-10-07）

通常起動する `App/City.exe` に水源から海への川を統合した。引き継ぎ作業用コピーだけにあった処理を、現在の本体の描画、地図の分割更新、チャンク単位の開発保存へ接続した。新規生成・保存読込の両方で使う。

内陸は水量ゼロから開始する。点水源が供給し、合流する河道の保存量・流量を更新して、海へ排水する。海は0mの一定水位で排水のみを受け、海からの流入は0。低地の河原は実際の地形に追従し、堤防は歩ける地形と接続した道路を持つ。橋と道路は将来の川の高さに備える。水面、周辺地図、全画面地図は実際の水量を使い、ゲーム停止中は水も止まる。

## 確認結果

Release本体とTestはエラー0・警告0。関連ケースは次のとおり成功した（フィルター間の重複を含む）。

| ケース | 成功 |
|---|---|
| `SourceWater` | 9 / 9 |
| `Rivers.` | 7 / 7 |
| `Transport.` | 26 / 26 |
| `Map` | 32 / 32 |
| `SaveTransaction` | 5 / 5 |

シード42では146,812区間、水源136か所、海への出口22か所、閉じた陸側終端0。地形としての堤防20地点も確認した。1日分の更新後、海への流量は8,704m³/sで、水源の全供給量と一致。海へ597,510,509.347m³を排出し、水収支の誤差は5.48362732e-06m³だった。平均の水更新時間は1.953ms。GPU読み戻しでも水面の表示と標高が正の地点の地図表示を確認した。

本体はリポジトリ直下の `App/City.exe` を `--seed 42 --low-spec --playtest-commands <作業用JSON> --new` で起動した。初期の小さな水面から、時間経過で下流へ連続する川に伸びることを同じ視点で確認。周辺地図・Mキーの全画面地図に青い水域が現れた。堤防道路27本を生成し、徒歩視点で道路上を0.460m移動して川と堤防の並びを確認した。

水の時刻29,670秒で停止し、専用セーブ `river_integration_review_20261007` に保存して正常終了した。最終ビルドの通常ゲームを `--low-spec --playtest-commands <作業用JSON> --load river_integration_review_20261007` で再起動し、時刻、水源数、注水量、保存量、海への排水量、海からの流入量、水収支をすべて完全一致で復帰した。再開後に時刻と排水量が増えることも確認した。スクリーンショットは内部で確認し、会話やこの記録には画像を掲載していない。

## 修正と範囲

取り込み時に一部の終点が丸められ、6個の陸側終端が残る問題を修正した。スプラインの最終点と経由点を正確に保持し、同じ境界出口を共有して海へ連続させた。従来の河川生成の既定も海への排水を維持する。地形・河川の22シード検証を含む既存の河川ケースも成功した。

河道の位置は生成時に決まる軽量な流量輸送方式で、プレイ中の侵食、氾濫、堰による流路変更は扱わない。地図の水更新は最大10秒間隔。最新の道路・描画準備の仕組みとチャンク単位の開発保存を維持し、旧作業コピーの不要な補助コードや研究用テストは追加していない。

元からあった17件の追跡済み未コミット変更は対象から除外した。数値、実行ID、本体の識別情報は [verification.json](verification.json)。全文ログ、操作JSON、差分適用前のバックアップは無視対象の `artifacts/local_runs/river_integration_20261007/` と `artifacts/local_runs/checks/` に保存した。
