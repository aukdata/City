# AI 指示の整理と検証（2026-09-18）

[OpenAI の記事](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)を踏まえ、常時必要な制約と作業別の手順を分け、不要な読み込み・重複・固定出力様式を減らした。

## 変更

- `AGENTS.md` は用途別の参照先を示す。仕様一式の必読をやめ、既読指示の再読、理由のない検証の反復を避ける。文書変更には差分・リンク・整合性の確認を適用する。
- `.codex/` の7ガイドを短縮し、既に整理済みの review/refactor は維持。Claude の9定義は短い説明と共通ガイドへの入口にする。モデル・ツール・名前の指定は維持した。
- ビルド手順を一本化し、VS 2022 の旧パス、通常編集での一括改行変換、鉄道の一律レビュー除外、ビルド失敗の無視を取り除いた。コミットと push の依頼範囲も区別した。
- 画像送信禁止、本体起動条件、Test での UI 先行検証、BOM/CRLF、街の生成方針、計測、警告対応、既存変更の保持、memory 不使用を維持した。

- 編集した20文書の相対リンクが存在することを確認。Claude 定義の name/model/tools が変更前と一致することを確認。
- MSBuild と Siv3D SDK の参照パスが実在することを確認。旧 VS パス、一括 LF 変換、鉄道を未完成扱いする記述が現行ガイドに残っていないことを確認。
- 用途の対応を確認: 文書修正は関連文書、コード修正は担当仕様・規約、ビルドは build、テストは Test、未確認 API はメモから SDK 調査へ進める。
- `git -c core.whitespace=trailing-space,space-before-tab,cr-at-eol diff --check` 成功。既存の CRLF を保持して検査した（既定の検査は一部 Markdown の CR を末尾空白として報告する）。
