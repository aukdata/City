# 高速道路の走行速度・案内標識・区画線・IC 周辺の見直し

2026-10-31。依頼（6 項目）:

1. 道路のつなぎ目で車が減速するため高速道路の走行速度が遅い。前後の制限速度の平均で走らせる。
2. 高速道路の案内標識を現実（NEXCO）に忠実にする。
3. 加減速車線と走行車線を区切る線は太く周期の短い破線にする。
4. 車線変更が短い距離で済んでいて横滑りに見える。
5. IC 前後: 料金所前後に車線の線を引かない、不要な登坂車線をなくす、方面の看板を置く、分岐で道路が裂けている。
6. 高速道路の経路決定でトンネルのコストを上げ、車線が多いほど高くする。

## 参照した資料

- 道路標識、区画線及び道路標示に関する命令（標識令）別表第二: 案内標識 108 の 2（方面と出口の予告）、108 の 3（方面と出口）、114 系（入口の方向）、118 の 2 系（方面と距離）。高速道路の案内標識は緑地に白文字。
- NEXCO 設計要領 第五集 交通安全施設編（標識）: 出口の予告を 2km・1km・500m に置き、500m 予告と出口（分岐点）は門型（オーバーヘッド）で車線の上に掲げる。出口標識は流出車線の上、本線方向の標識はその右の走行車線の上。出口番号は白地の角丸枠、路線番号（E 番号）は高速道路ナンバリングの緑地白縁のバッジ。
- 区画線: 車線境界線のうち加速・減速車線（変速車線）との境界は「太い破線」（車道外側線と同じく幅 45cm 程度）。線長・間隔は資料により 3〜6m の幅があり、走行車線の境界（8m / 12m）より明らかに短い周期として 3m / 3m を採用した（推定）。
- 料金所前後（料金所広場）はブースへの寄り付きのため車線境界線を引かない。

## 変更

- つなぎ目の速度（`src/traffic/VehicleManager.cpp`）
  - 高速道路だけが集まる節点（本線の継ぎ目・分合流）では、交差点の固定目標 8m/s の代わりに前後の制限速度の平均（運転者ごとの係数込み）を目標にする。接続経路の曲率から横加速度 2.5m/s² 以内の速度で上限を掛ける。
  - 進入時の 0.9 倍の減速をつなぎ目では掛けない。制限超過は 2m/s² で穏やかに落とす（瞬間的に切り捨てない）。前方 200m 以内のつなぎ目の目標速度へ向けて先に減速する。
- 車線変更（`TrafficCommon.hpp`, `Vehicle.hpp`, `VehiclePose.cpp`）
  - 所要時間を 0.5 秒固定から速度依存（1.5 秒＋0.09 秒×速度 m/s、上限 4.5 秒。100km/h で約 4 秒）にした。横移動は S 字（smoothstep）で始まりと終わりがなめらか。車体は横移動の分だけ向きを変える。
  - 区間の終わりまでに収まらない経路上の車線変更は 0.8 秒まで縮め、任意の追い越しは見送る。
- 区画線（`RoadTypes.hpp`, `RoadRenderer_Markings.cpp`, `ExpresswayCrossSection.hpp` ほか）
  - `LineType::DashedWhiteThick`（幅 0.45m、3m / 3m）を追加し、変速車線と本線の境界に使う。道路の詳細パネル・図にも反映。
- IC 前後（`ExpresswayNetwork.cpp`, `ExpresswayCrossSection.hpp`, `RoadNetwork_Connections.cpp`）
  - 料金所前後の取付区間（ランプ足元 → 料金所 → ランプ足元）を 2 車線の 1 本の区間にし、区画線を引かない。料金所前後の幹（ステム）も線なし。
  - ランプが料金所側の節点から同じ位置で 2 本出て重なっていた（裂けて見えた）のを、足元で左右へ車線幅の半分ずつずらして分けた。
  - 一般道への取付道路を片側 1 車線ずつにした（2+1 車線が登坂車線に見えていた）。
  - 高速道路だけの節点の車線接続で、向きが逆の接続（U ターン）を作らない。
- 案内標識（`ExpresswayNetwork.cpp`, `GuideSign.cpp`, `RoadRenderer_Signs.cpp`, `GuideSignStorage.cpp`）
  - 旧来の 1 枚の案内板を廃止し、NEXCO の体系で並べる。
    - 出口予告 2km・1km（路側）: 出口番号枠＋IC 名＋距離。
    - 500m 予告（門型）: 出口板「[番号] ○○IC 出口 EXIT 500m / 行き先」と、右に本線方向板「[E 番号][路線名] 行き先 ↑」。
    - 出口（門型、減速車線の上、分岐点の手前）: 「[番号] ○○IC 出口 EXIT / 行き先 ↖」。
    - JCT は分岐先の路線番号・路線名、SA は出口番号なしで同じ形。
    - 合流の先: 方面と距離の一覧（次の IC・終点方向の町と km）。
    - 料金所の先の分岐（上り・下り）: 門型に左右の方面板（↖ / ↗）。一般道側の入口に入口案内。
  - 門型の支柱とトラスを描く。支柱は防護柵の外と中央分離帯。板の色は sRGB の NEXCO 緑（線形化して描く）。
  - 看板要素に角丸の板（番号枠・路線名）、文字色・地色・揃えを追加し、保存・読込にも追加した（旧セーブはそのまま読める）。
- トンネルのコスト（`RailCostProfile.hpp`, `ExpresswayNetwork.cpp`, `expressway.json`）
  - `expressway.json` の `tunnelCostScale`（既定 3）と、片側車線数の 1.5 乗（2 車線を 1）をトンネルの単価に掛け、回廊探索と縦断計画の両方に使う。seed 42 ではトンネル区間が 548 → 331 エッジに減り、本線が地表・高架へ移った。

  - `Expressway.CrossesMapWithInterchange` の監査: 太い破線の変速車線境界がある、料金所前後の区間に区画線がない、門型の標識がある、2km/1km/500m 予告がある。

  - 途中、継ぎ目の速度を一般道の 2 本接続の節点にも適用したところ `Traffic.AutomaticTripsAndRespawn` が落ちた（12 角形の街路でトリップ完了 2 件）。対象を高速道路だけの節点に絞り、23 件で通過。

## 残る課題

- 区画線の線長・間隔（3m / 3m）は資料から確定できず推定値。
- 標識の文字組みは BoardBuilder の近似で、標識令の字高・余白の比率は厳密ではない。
