# 統合リファクタリング

ルールの正本は [AGENTS.md](../AGENTS.md)。書式は [CODING_STYLE.md](../CODING_STYLE.md)、検証は [Test/AGENTS.md](../Test/AGENTS.md) を参照する。このガイドにビルド環境・承認条件・改行変換などの別ルールを重複定義しない。

1. 作業ツリーと現行仕様を調べ、既存の変更を保護する。
2. 呼出経路と所有権を追い、具体的な根拠と完了条件を [REFACTOR.md](../REFACTOR.md) に先に記録する。
3. 重複する判断は一つにまとめる。評価方針や更新頻度が違うものを、名前が似ているだけで統合しない。
4. 主要な境界・単位・制約の理由を日本語コメントで説明する。関数名の言い換えだけのコメントは増やさない。
5. 移設だけの関数は本体の一致を確認し、共有化した計算は独立した基準・境界条件・既存テストで検証する。
6. 関連ビルドとテストを通し、構成案内・チェックリスト・検証結果を更新する。変更の記録方法はルートの指示に従う。

現在の配置とデータの所有権は [コード構成](../plan/29_code_architecture.md) を参照する。
